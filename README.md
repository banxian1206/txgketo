# 同兴高科 项目管理系统（txgketo）

**客户**：广东同兴高科智能装备有限公司（TXGK / 品牌 TXAM）——非标自动化装备与整线制造商
**业务**：商机 → 立项 → 工程设计（设计BOM + 材料BOM）→ 采购 → 仓库 → 制造 → 装配调试 → 发货发运 → 现场安装 → 现场调试 → 客户验收 → 质保售后
**约束**：纯内网私有部署，**不集成任何外部系统**；手机端是主要终端（仓库/车间/现场没有固定办公地点）
**规模**：公司约 30 人使用 → 单机 Docker Compose 部署，不上集群/微服务/Redis

### 已跑通的链路（S0 → S11，接口级端到端测试过两轮）

```
建商机（必选销售负责人）→ 成交登记（金额/周期/质保/付款节点）→ 立项（团队/设备/节点/长周期件/派任务）
→ 出图 + 设计BOM + 材料BOM + PLC程序 → 勾选提交评审 → 经理 → 总监 → 发布=冻结
→ 自动进采购池（标准件/定制件/原材料/外协件）→ 合并下单 → 到货验收 → 入库 / 领料
→ 排产（自制件：下发/验收/转运）+ 外协（发出/回厂/验收）→ 齐套率 → 装配 → 厂内调试
→ 发货指令 → 按结构生成发运清单 → 逐项勾「已发」+拍照 → 装车 → 分批发运
→ 现场：按同一份清单逐项清点（到/缺/损）+ 直发件清点 → 每日汇报 → 现场问题立 ECN（总监批准→派改版）→ 申请调试
→ 客户验收（资料包/签字）→ 自动质保 12/18 个月 → 售后工单（在保判定）→ 关单；回款逐笔登记
冻结后要改 → 提改版申请（CR）→ 总监裁决/下发 → 改版出新版 → 重走两级审核 → 新版本发布、旧版留档
```

## 三、怎么跑起来

```bash
./dev.sh          # 一键：数据库 → 后端 :8208 → 前端 :5207
./dev.sh stop     # 停后端与前端

# （可选）生成演示账号（19+5 个，密码 txgk@123；管理员 admin/admin12345）
(cd backend && .venv/bin/python -m scripts.seed_demo_users)

# 测试脚本（都走真实 HTTP 接口）
(cd backend && .venv/bin/python -m scripts.seed_s0_s1)        # 清库 + 重建物料 + 只走 S0→S1
(cd backend && .venv/bin/python -m scripts.e2e_full_test)     # S0→S11 基础链路
(cd backend && .venv/bin/python -m scripts.e2e_complex_test)  # S0→S11 高复杂度（多设备/同型/分批/返工/两批发运/ECN）
```

| 用途 | 地址 |
|---|---|
| 前端 | <http://127.0.0.1:5207> |
| 接口文档 | <http://127.0.0.1:8208/docs> |
| 账号 | `admin` / `admin12345`（上线前必须改） |

**端口**（已登记于 `../PORTS.md`）：前端 5207 · 后端 8208 · PostgreSQL 35432

> ⚠️ **本机 Docker 注意**：compose 文件顶层必须写死 `name: txgketo`，启动必须带 `-f`。
> 本机多个项目都用 `deploy/` 目录，Docker 默认以目录名作项目名会撞车（详见 `../PORTS.md`）。
