## 3. ★ 新发现

### N13 [P1] 直发 × 拆单：到货单数量按【需求总量】建，不按【单行量】→ 实收翻倍

**位置**：`api/routes/initiation.py:1142`，`_ensure_site_pending_receipt()`

```python
gr = GoodsReceipt(
    ...
    qty=row.qty,          # ★ 需求总量
    qty_ok=row.qty,       # ★ 需求总量
```

这个函数在 N12 修复里**被改过**（`line` 参数已传进来、幂等判断已改成 `GoodsReceipt.po_line_id == line.id`），
但**只改了"归属"，没改"数量"** —— `line` 参数拿到了却没用于 `qty`。

**实测**（`/tmp/txgk_v5.py` V5-A）：需求 `板材×60` 拆给 甲30 + 乙30，两张都直发客户现场：

```
采购单行   = [(25, 'PO26023', 30.0), (26, 'PO26024', 30.0)]     ← 各 30，正确
现场待验收 = [('GR26010', 60.0, '现场待验收', po_line_id=25),
              ('GR26011', 60.0, '现场待验收', po_line_id=26)]   ← ★ 各 60！

清点第一张后：需求 qty=60  qty_received=120  status=现场待验收
两张都清点后：需求 qty=60  qty_received=120  status=现场已验收
```

| 影响 | 状态 |
|---|---|
| **净需求/重复采购** | ✅ **不受影响** —— 他们把 `_open_qty` 改成按**整条 `qty`** 抵扣（`bom_demand.py:69-72` 注释明确说明原因），所以 `qty_received` 虚高不会导致漏采/重采。这是个好设计决策 |
| 现场清点依据 | ❌ 现场看到两张各「60 个待清点」，实际每家只发 30 → **按 60 清点会判虚报缺件，按 30 确认则与单据不符** |
| 需求"实收数量" | ❌ `qty_received=120 > qty=60`，订购量的 **2 倍** |
| 供应商绩效 | ❌ 合格率/交货量分母错：乙（发 30）被记成交了 60 |
| 对账 | ❌ 单据显示量与实际发货量不一致 |
| 归属正确性 | ✅ `po_line_id` 各自挂对（25/26），清点一张不影响另一张 |

**修复**：`line` 存在时用行量

```python
q_ = float(line.qty or 0) if line is not None else float(row.qty or 0)
gr = GoodsReceipt(..., qty=q_, qty_ok=q_, ...)
```

**同源扫描**（已做，结论乐观）：
- 全库 `qty=row.qty` **仅此 1 处**残留
- 另两处 `GoodsReceipt(...)` 创建点（`initiation.py:1376/1394`，部分合格路径）用的是 `qty=ok` / `qty=rejected`（来自 `body`，行级正确）✅ V5-B 已实测确认
- 即：**N12 那一类共 6 个触点，已修 5 个，N13 是第 6 个**

## 4. 一个模式提醒（这是同一类问题第 3 次出现）

| 轮次 | 同根问题 |
|---|---|
| 第 1 轮 | `merge_order` 用 `row.qty = ln.qty` 覆盖**需求**数量 |
| 第 2 轮 N12 | `_bump_line_on_receipt` 猜"最新一行"记到货 |
| 第 3 轮 N13 | `_ensure_site_pending_receipt` 用**需求**总量建**行**级到货单 |

根因始终是同一句话：**`purchase_request`（需求）和 `purchase_order_line`（单行）是 1:N，凡是"到货/收货/记账"的环节，数量必须取自行，归属必须落到行。**

建议在修 N13 时顺手加一条**静态护栏**（项目已有同类做法，如 `PREFILL-无先设后开`、`R4-01-移动不链PC台`）：
> 扫 `app/**/*.py`，凡是 `GoodsReceipt(` 构造里出现 `qty=row.qty` / `qty=request.qty` 即失败；
> 到货单的数量必须来自 `body`（仓库实收）或 `line.qty`（单行订购），不能来自需求。

并补一条 e2e 交叉护栏（本轮我已验证可跑）：**直发 × 拆单 → 两张到货单各 = 行量，清点后 `qty_received ≤ qty`**。
