## 3. 第一轮具体交付

首轮聚焦登录、S0、S1，边界到机械经理收到任务。交付该段页面与交互的实际修改、同角色同视口的前后截图、问题修复记录和行为护栏。

优先处理来路丢失、立项保存整页加载、无数据提示不准确，再处理表单进度、字段标签、成交付款表与信息层级。保留现有分区值不丢、错误自动跳区、发号、权限与审批规则。

公共基础只改到当前闭环需要的范围：标题与主要动作、返回上下文、保存反馈、表单错误、空态。问题在第二个页面重复出现时沉淀到现有公共组件；避免一次性重写所有台或在 CSS 尾部不断叠覆盖。

## 4. 每批验收标准

1. 首屏能回答：我在哪、当前什么状态、下一步做什么。
2. 搜索 / 列表能找到完整结果；编号、名称、规格、状态可直接区分。
3. 主动作明确；禁用说明原因；成功有结果；失败保留已填内容，避免重复提交。
4. 切区、刷新、详情返回尽量保留用户上下文；适用状态进 URL，遵循已有导航规范。
5. 同类控件、文字、状态、工具条、空态使用现有标准。按首屏有效信息评估，不能机械压低页高。
6. 手机无页面整体横溢出，触控目标按既有规范，键盘与固定按钮不互挡；拍照和弱网需真实验证。
7. 用责任角色本人账号验证上游完成与下游收到；空态、有任务、异常、无权限均覆盖相关分支。

测试沿用专用项目 TX26001 或隔离测试库；不能为截图运行 e2e:clean，保护已导入 ERP 数据。必要测试数据新增通过正常业务链，不使用 admin 绕权限。

功能 / 行为变化按 AGENTS §4 回档交互、视觉、执行计划及进度，补对应真实行为护栏。实现后执行前端 build + tsc、适用静态 / UI / API 检查；后端变更跑相应 pytest。仅文档走查不声明产品全绿。

## 5. 工作量管理

为每批维护“问题 → 页面 / 公共组件 → 改动 → 验收任务 → 截图 → 状态”的清单。按阻断任务、容易选错、增加步骤、视觉细节排列优先级。每次只完成一个连续闭环，验收后进入下一段；共性修复同步覆盖已经完成的页面。

实际工作量需在每批有数据走查后确认，不先承诺整站工期。当前已完成整体地图和前半程基线，可以从第一批开始精调。
