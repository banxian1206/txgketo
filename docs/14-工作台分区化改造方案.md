# 14 · 全站分区化改造方案（一套壳 + 一张注册表，覆盖全站）

> 2026-10-05 ｜ 需求来源（用户原话）：
> **「所有的界面都是卡片，一个一个往下摆放的，我想把它变成 tab，可以切换，这样就不用一直往下滑，就能看到整个工作台的内容。」**
> 追问：**「范围是很广的，每一个工作台里面的详情都是这样的 —— 这是不是一个框架应用到所有的地方？」**
> 状态：**方案待拍板，未开工**（§7 有 6 件要你点头的事）

---

## 0. 先给结论：你问对了 —— 该做的是一套框架，不是逐页优化

**实测：31 条 PC 路由里，11 条 ≥1.3 屏，9 条有 3 个以上纵向块。**
而且我上一版漏掉的**最大的两块**是 —— **立项页 2297px（2.6 屏）** 和 **新建商机 1560px（1.7 屏）**，
它们本来就是 `① ② ③ ④ ⑤ ⑥` 分节的表单，**比档案页更该分行摆放**。

所以正确做法是：

```
一张注册表（每页声明它有哪些分区）
        ＋
一个壳（结论常驻 + 分区条 + 当前分区内容）
        ↓
按「页型」批量套用（不是逐页手改）
```

**一句话**：把"页面上摆什么"从**各页自由发挥**，改成**声明式**（`sections: [{key,label,badge,render}]`），
壳统一负责分区条 / URL / 徽标 / 结论常驻 / 键盘 / 空态。

## 2. 框架设计（这才是本次要建的东西）

### 2.1 三个原语

| 原语 | 放哪 | 作用 |
|---|---|---|
| **`PageFrame`**（结论常驻区） | 页面顶部 | 标题/编号/状态 + 主操作 + **关键数字条** + **卡点一行** —— 切分区时**不动** |
| **`SectionNav`**（分区条） | 结论区下方 | 一等高分区块（带**计数徽标**），超出横滚；**sticky**；`?tab=` 进 URL；←/→ 可切 |
| **`SectionBody`**（分区内容） | 分区条下方 | 当前分区内容；**或** `SectionPanel`（同一张 Panel 内的分节，用 `.ds-subhead` 分隔，**不再画 N 个卡框**） |

### 2.2 关键取舍：**结论常驻 + 分区切换**（不是纯 tab）

```
┌─ 常驻（切区不动）──────────────────────────────────────────┐
│ ← 返回项目  01A 贴胶机  [已装配]            [进设计面][刷新] │
│ 齐套 100% · 图纸 4 · 排产 1 · 外协 1 · 发运 1 · 售后 1      │  ← 跨区对比靠它
│ ⚠ 还缺 1 项：外协未回厂 WX26001（约定 10-15）               │  ← 最要紧的一句
├─ [概览 2] (图纸 3) (制造 2) (装配 1) (发运 1) (现场 4) (售后) (时间线) ─┤  ← 分区条
├─ 当前分区内容（通常 1 屏内）───────────────────────────────┤
```

**为什么不做纯 tab**：一次只显示一区，就**看不了"缺什么 + 谁在干 + 货到哪"的并排关系** ——
而这恰恰是本系统最常被问的。结论常驻后：**不用往下滑，也不丢一眼看全**。

### 2.3 分区条形态：**不用下划线 Tab**

一屏**只允许一条页签条**（现有护栏 `TAB-一屏一条页签条`），台类页已经占了那一条。
档案页再用下划线 Tab → 两条一模一样的条，分不清"哪条是台、哪条是页内分区"。
所以分区条是**更轻的一等高分区块**（与台内 Segmented 同族、比它高一档）。

### 2.4 声明式注册表（框架的核心）

```ts
// configs/sections.ts —— 每页声明自己的分区（元数据集中，渲染函数留在页面里）
export const EQUIPMENT_SECTIONS = [
  { key: 'overview', label: '概览',   badge: (d) => d.blocked.length || undefined, default: true },
  { key: 'drawing',  label: '图纸',   badge: (d) => d.drawings.length },
  { key: 'mfg',      label: '制造',   badge: (d) => d.prod_orders.length + d.outsource.length },
  { key: 'assy',     label: '装配',   badge: (d) => d.assembly.length },
  { key: 'ship',     label: '发运',   badge: (d) => d.shipments.length },
  { key: 'site',     label: '现场',   badge: (d) => d.site_dailies.length + d.site_issues.length },
  { key: 'svc',      label: '售后',   badge: (d) => d.service_orders.length },
  { key: 'timeline', label: '时间线' },
] as const
```
**为什么进注册表**：① 一处能看到某个页面会分几区、默认哪区；② 徽标口径统一；③ 护栏能静态校验
（"每页分区 ≤ N""分区必须覆盖所有块，不许有块没归属"）；④ 与已有的 `configs/tabs.ts`（台内页签）同族。

**规则（写进护栏）**：
1. **一屏最多 1 条台页签 + 1 条分区条**（不许两条同类）；
2. **分区不嵌套**（分区里不许再出现分区条/Segmented 视图切换）；
3. **每个块必须归属某个分区** —— 不许有"孤儿卡"（这正是当前 12 个 `*Card.tsx` 的状态）；
4. **空分区保留**（显示"这一项还没有记录"+ 去干这件事的入口），不许隐藏（隐藏会让人以为系统没这功能）；
5. **默认分区**：档案/详情 → 概览（卡点优先）；表单 → 第一步；设计面 → 图纸与 BOM。

| # | 护栏 | 类型 | 内容 |
|---|---|---|---|
| 1 | `SHELL-一屏最多两条横条` | static | 一屏最多 1 条台页签（`<Tabs\|<WorkbenchTabs`） + 1 条分区条（`<SectionNav`）；同类两条即红 |

| 4 | `OBJ-结论常驻` | ui | 切到任意分区，**状态/关键数字/卡点仍在首屏可见**（防有人把结论塞进某个 tab） |

## 6. 代价与风险（先说清）

1. **纯 tab 的代价是"看不见别的区"** → 用"结论常驻 + 徽标"补回来。若你要"一屏里同时看两块"（如"缺件 + 谁在干"并排），那就不该分区化。
2. **分区条是新的一层导航** → 必须守住"1 台页签 + 1 分区条"，否则会退回 docs/12 批过的"三层标题"。
3. **表单页分区的副作用**：跨分区校验（提交时要看到全部错误）—— 需要"分区条上显示错误数徽标 + 点提交自动跳到第一个出错分区"。
4. **断言迁移不能只删不补**：每条都要**注入反例自证能红**（本项目一直的规矩）。
5. **移动端明确不做**（一屏一件事已经比 tab 更彻底）。

### P5 去卡化 ✅（2026-10-05）

**做法：一条作用域 CSS，而不是改 20 个文件。**
```css
.ds-sec-body { background/border/radius/shadow; padding: 4px 16px }   /* 分区体 = 一张纸 */
.ds-sec-body .ds-panel, .ds-sec-body .ant-card { border:0; radius:0; shadow:none; bg:transparent }
.ds-sec-body .ds-panel + .ds-panel, … { border-top: 1px solid var(--ds-line) }   /* 块之间 = 发丝线 */
```
- 为什么这么做：这些块来自**不同组件**（项目详情 12 个 `*Card.tsx`、工程台 10 张卡、各台内的分组卡…），
  逐个改既慢又容易改错；而"去框"本身是**纯视觉**的，作用域内统一即可（可回退、零逻辑风险）。
- 效果（实测「范围与资料」区）：原来是 **3 个并排白框**，现在是**一张纸上的 3 个分节**（项目要求 / 齐套率 / 资料包，发丝线分隔）。
- 空分区不套纸框（`:has(> .ds-sec-empty)` 豁免，免得一句人话被框住）。
