# 24 · 项目全生命周期时间线

日期：2026-10-07。状态：**已落地**（后端 + 前端 + 护栏）。

## 1. 客户口径（原话）

> 「我就是想做一个整个项目的全生命周期的一个时间线放在这里……从商机建立到最后的项目结束。
> 比如说商机这个时间段，然后商机到立项这个时间段……工程的周期我们不是会有一个节点设置嘛？
> 把那个时间拿上来。但是这些节点它是会**重叠**的，它不是一条串行，它是**并行**的……
> 然后今天这个时间，然后回款的时间也在这个线上……」
>
> 「不用这么多时间节点在那个上面，太多反而杂乱……中间只有几条线：今天（红线）、回款节点的线。」

## 2. 六个时间源（全部来自已有表，**不新增业务表**）

| # | 时间源 | 来源字段 | 形态 |
|---|---|---|---|
| ① | 商机记录 | `project.created_at` | 时点 |
| ② | 立项 | `project.initiated_at`（★ 本次新增） | 时点 |
| ③ | 里程碑 | `milestone.plan_start/plan_end` | **段（可重叠 → 甬道）** |
| ④ | 交付截止 | `project.delivery_end_date`（应交日单一口径） | 时点 |
| ⑤ | 质保期 | `warranty_start` / `warranty_end` | 段 |
| ⑥ | 回款 | `payment_term.expect_date` / `received_date` | 时点 |

接口：`GET /api/v1/projects/{project_no}/lifecycle`（**只读聚合**，登录即可）。
前端：`components/project/LifecycleTimeline.tsx` → 挂在 `ProjectSummaryBar` 的「生命周期」面板里，
取代原来的 `Rail`（阶段条）——**一个页面只留一条生命周期**（txam 也没有阶段条）。

## 3. 三条设计决策

### 3.1 里程碑**按重叠自动分甬道**
客户明说「工程设计 / 采购 / 生产会重叠」。算法是贪心：

> 按开始时间排序 → 谁和已在某道上的段时间区间重叠，就往下挪一道。

所以甬道数**是数据算出来的**（同一份数据里 TX26001 是 1 条道，并行的演示项目是 4 条），
以后加节点（外协、调试…）它自己会找道，不用手工排。

### 3.2 标签不重叠：**同日合并 → 贪心错排 → 边缘钳制**
真实数据里 `商机记录` 和 `立项` 都在 `10/06`，两个标签会**完全叠在一起糊成一团**（实测）。
处理分三种情况：

| 情况 | 对策 |
|---|---|
| 同一天 | **合并成一个标记**：`商机记录 · 立项 10/06`（同一时刻发生 = 一件事） |
| 挨太近（不同天但会压上） | **贪心错排到下一行**（与甬道同一个算法） |
| 贴左右边缘 | **钳制到边界内**；时间位置仍由虚线精确标出 |

同一套算法用在**三处**：事件轨、回款轨、甬道 —— 所以以后数据再密也不会糊。

### 3.3 状态**不在前端算**（单一口径）
「完成 / 延期」以前谁也没算过（只有人工 PATCH 写 `milestone.status`）。
现在集中在 **`services/deadline.py::milestone_state()`**，接口下发 `state`，前端只做颜色映射：

```
① 有实际完成日 或 状态=已完成 → 已完成
② 计划结束日 < 今天、且没完成  → 延期
③ 计划开始日 > 今天            → 未开始
④ 其余                        → 进行中
```

理由：车间台、超期扫描各自也有一套“算不算超期”，前端再算一套就是
AGENTS §8.5 那条「同一个概念在多处各算一套」（六通道六种答案的翻版）。
护栏 `LIFE-时间线接线与状态口径` + `test_project_lifecycle.py` 双重钉住。

## 4. 质保期**不按比例**

质保常是 12 个月，而项目执行期只有 5 个月 —— 按真实比例画，质保段会占掉七成宽度，
把前面全压成一条线。所以**固定占 11% 的尾巴**（txam 同手法），并在 hover 里说明「不按比例显示」。

## 7. 已知数据缺口（不是设计问题）

1. **里程碑的「实际」没有来源** —— `actual_start/actual_end` 只有人工 PATCH 能写，业务流程不会填。
   所以现在这条线画的是**计划**；客户要的「事情按发生时间落上来」还需要：
   把设计发布（`drawing.published_at`）、下单（`purchase_order.order_date`）、到货（`line.actual_arrive_date`）、
   发运（`shipment.depart_at`）、验收（`acceptance.accepted_at`）这些**已有的时间戳**接进里程碑。
   （这些字段系统里都有，缺的是“谁把它们写进 milestone.actual_*”这一步。）
2. **回款计划日为空**：`payment_term.expect_date` 在演示数据里没填 → 时间线上没有回款胶囊。
3. 存量项目的 `initiated_at` 只能从审计日志回填；审计日志被清理过的项目会缺这一段。

## 8. 观感上的取舍（写下来免得以后被改回去）

- **段上用短名**（设计 / 采购 / 制造 / 装配 / 发运 / 安装 / 调试 / 验收），全名进 hover ——
  全名会把格子挤成「装...」，就是客户说的“杂乱”。
- **「今天」单独占一条标签带**（甬道上方 18px），否则红字会压在第一条上。
- 刻度跨年带年份（`27/01/04`），同日去重，相邻太近错行。
