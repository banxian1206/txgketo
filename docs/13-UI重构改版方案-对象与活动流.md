# 13 · UI 重构改版方案（以「对象 + 活动流」为中心）

> 2026-10-04 ｜ 作者：AI（读完整条业务线后提出）
> 前置阅读：`00 卷 §2.1`（系统要成为什么）、`docs/12`（P0–P6 已做的渐进重构）、`docs/10`（信息架构）、`docs/11`（导航上下文）、`前端UI视觉规范`、`前端交互设计规范`
> **本方案不是推翻 docs/12 的成果** —— P0 的 token、P1 的结论条、P2 的计数单源、P3 的筛选进 URL、P6 的列治理**全部保留并复用**。
> 推翻的是**页面骨架的选型**：现在整套 UI 是「**按部门切页面**」，业务本身是「**按项目走一条线**」。

---

## 0. 一句话结论

**继续按 docs/12 的路子优化，收益已经见顶** —— 剩下的问题不在字号/间距/列数，而在**导航模型**：
系统有 12 个阶段、10 个部门台、51 个页签、18 类编号，而用户手上永远只有**一个对象**（一个项目 / 一台设备 / 一个件 / 一张单）。

**改版主张：三层新骨架 = 收件箱（我今天干什么）+ 对象档案（编号即入口）+ 活动流（谁在什么时候干了什么）**，
把「部门台」从**导航主体**降级为**过滤条件**。

| 决定 | 内容 | 为什么 |
|---|---|---|
| **不推倒** | 组件库（antd 5）、token（FS/SP/MONO/T）、`theme/status.ts`、`useUrlState`/`useTab`/`useFrom`/`contextPath`、结论条+泳道、列治理成果、全部 e2e 断言的**判定逻辑** | 这些是资产，重做等于自伤 |
| **推倒重来** | 页面骨架（Card+Table+Tabs 三件套）、导航模型（侧栏+台+页签）、待办的组织方式（每页各数各的）、移动端「清单页」的写法 | 见 §2 实测 |
| **新增** | 三个对象档案（设备 / 件 / 单据）、一条活动流、一个收件箱、一个驾驶舱 | 见 §1，**00 卷 §2.1 早就承诺，UI 上根本不存在** |

## 1. 先回到业务：00 卷承诺的七个视角，UI 上有没有？

`00 卷 §2.1「系统要成为什么」`逐条对照实测（截图见 §2）：

| # | 文档原话（客户视角） | 现在有没有 | 缺什么 |
|---|---|---|---|
| 1 | **对项目经理**：一个页面看清项目全貌——进度、**卡点**、缺料、变更、问题、成本 | ⚠️ 半个 | 详情页给的是**静态字段**，不给「卡在哪、谁该动」；要自己一条条泳道点开找 |
| 2 | **对设计**：图纸有版本、有审核、有发放记录，改图有变更单 | ✅ | — |
| 3 | **对采购/仓库**：知道「**哪台设备的哪个件**还没到」，齐套一目了然 | ⚠️ 半个 | 齐套率有（百分比+漏斗），但**点不到那个「件」**——件没有档案，只能回采购池搜物料 |
| 4 | **对车间**：今天干什么、**按哪版图干**、干完拍照 | ⚠️ 半个 | 排产单列表有，但「按哪版图」要进弹窗才知道；图号/版本不在卡片面上 |
| 5 | **对现场**：今天到几车货、装了哪些、缺什么、客户签了什么字 | ✅ | — |
| 6 | **对总经理**：在手订单、交付风险、项目毛利、售后质量，**一屏看完** | ❌ **完全没有** | 驾驶舱在三期，未开工。实测 gm 登录后：「我的任务 0」「我提的改版 0」「系统管理入口」「最新消息（未读 0）→ 没有消息」「我参与的项目 → 还没有参与的项目」，**四张空卡占满上半屏，剩下 60% 是空白** —— 一个经营视角该看到的东西一个都没有 |
| 7 | **对售后**：这台设备**全部历史**（图纸版本/装配人/检验/发运/现场改动/维修）都在 | ❌ **完全没有** | 客户已定不做二维码，但**「设备档案」这个视图本身没做** —— 售后只能翻发运台+现场台+售后台三处 |

> ★ **这就是"重新优化 UI"最该做的事**：不是把表格调得更漂亮，而是**补上两个承诺了但根本没画的视图**（#6 驾驶舱、#7 设备档案），
> 和**三个"看得见但点不动"的断点**（#1 卡点、#3 件、#4 按哪版图）。
> 这三件事全都指向同一个缺失：**没有"对象档案"这一层**。

### 1.1 业务结构决定 UI 结构（三条硬事实）

| 事实 | 对 UI 的要求 | 现在的 UI |
|---|---|---|
| **一个根对象** `project`，`project_no` 一生不变（07 卷 §0.1） | 主导航应该是**对象**，不是部门 | 主导航是部门台 |
| **一条线 12 个阶段**（S0→S11），阶段决定"下一步做什么" | 需要一条**看得见的轨道** | 阶段只是一个 Tag + 详情页 7 段步骤条（不可点、不显示卡点） |
| **18 类编号 + 30+ 组状态词**（07 卷 附A/附B） | 需要**粘编号直达**（搜索/命令面板） | ❌ 全站只有 4 处 `Input.Search`（项目列表/标准库/供应商/用户），全部是**各自列表内的模糊搜**，没有"粘编号直达" |

### 2.3 为什么"再优化一轮"收益见顶

docs/12 的 P0–P6 治的是**局部**（字号、列数、计数单源、URL、触控）。上面 10 条里：

- **只有 3 条是局部 bug**（日期列遮挡、「未收 ¥0」三态、两处「卷 §」上屏）—— 它们进 R0，半小时的事；
- 其余 7 条全是**结构**问题：三层导航 = 导航模型错；14 个数字格 = 没有"今天"这个概念；同物料 5 张卡 = 没有分组；两行长 Alert = 没有"帮助"这个位置；gm 空屏 / 件与设备无处可查 = **没有对象层**。

> **在 Card+Table+Tabs 的骨架里，这些问题会反复长回来** —— 因为骨架本身按"部门"切，业务按"项目"走。

## 3. 新骨架：三层

```
┌─ 全局层 ────────────────────────────────────────────────────────┐
│ ① 命令栏（顶部，常驻）：粘任意编号 → 直达（TX/PO/GR/MI/PR/WX/FH/SV/RV/RL/CR/TK/PC/图号/物料号）│
│ ② 收件箱（默认落地页）：我今天所有待办，按「阻塞别人 > 超期 > 今天 > 本周」排序，一条 = 一个动作      │
├─ 对象层（★ 新增，改版的核心）──────────────────────────────────────┤
│ ③ 项目档案（作战室）＝ 轨道 + 卡点 + 泳道 + 活动流                    │
│ ④ 设备档案（新）＝ 这台设备的设计/料/做/装/发/修 全部历史（00 卷 #7）    │
│ ⑤ 件档案（新）＝ 一个图号/物料号的一生：BOM→需求→PO→验收→领料→排产→装配→发运→售后 │
│ ⑥ 单据档案（统一）＝ 任意一张单（PO/GR/MI/PR/FH/SV/RV/CR/PC）的详情     │
├─ 视图层（保留，降级）──────────────────────────────────────────────┤
│ ⑦ 部门工作台 ＝ 对象层的**过滤视图**（队列 + 批量动作），不再是导航主体   │
│ ⑧ 主数据 / 系统管理 ＝ 不变                                          │
└──────────────────────────────────────────────────────────────┘
```

**关键转变**：`部门台` 回答「我是采购，我的活儿在哪」；`对象档案` 回答「这个件/这台设备现在怎么样」。
**今天只有前者**。业务上 80% 的追问是后者（"01A 那台还缺什么"、"这批方通是给谁的"、"这台设备当年谁装的")。

### 3.1 五个新原型（替代 Card+Table+Tabs 的自由组合）

| 原型 | 干什么 | 用在哪 | 替代什么 |
|---|---|---|---|
| **`Rail`** 生命周期轨道 | 12 段横向轨道，每段显示：状态色 + 计划/实际日期 + **卡点数**；点一段 → 跳到对应档案段 | 项目档案头、驾驶舱、PM 台每行 | 详情页的 7 段 antd `Steps`（现在不可点、不显示卡点） |
| **`Ledger`** 队列 | 统一的工作队列：分组（按单/按项目/按供应商）+ 行内主操作 + 批量条 + 空态引导 | 全部 10 个台的所有页签 | 97 张 `<Table>` 中的 ~60 张 |
| **`Dossier`** 对象档案壳 | 头部（编号+状态+责任人+关键数字+下一步）+ 分段（概览/结构/单据/时间线/附件） | 项目/设备/件/单据四类对象 | 4 套各写各的详情（详情页 + 3 个 Drawer + N 个 Modal） |
| **`Stream`** 活动流 | 把 audit_log + 状态变更 + 照片 + 站内消息合成**一条可过滤的时间线** | 每个档案的「时间线」段；收件箱的"最近发生" | 现在分散的：操作记录卡、消息抽屉、各单据的「流转记录」 |
| **`Job`** 移动作业卡 | 一屏一件事：清单 + 勾选 + 拍照 + 吸底主按钮 + **离线暂存** | 全部 /m/* | 现在 10 个移动页各自手写的卡片列表 |

> 五个原型全部**建在 antd 之上**（不引新依赖，AGENTS §3），复用现有 `Primitives`（`Stack/Muted/FieldGrid/CodeNo/NumCell`）与 `theme/status.ts`。

### 3.2 收件箱（把「我的工作台」升级成"今天"）

```
┌ 收件箱 ─────────────────────────────────────────────┐
│ 排序：🔴 阻塞别人 3 · 🟠 今天到期 5 · 🔵 本周 12 · ⚪ 已读归档 │
│ ┌ PO26034 待你审批（采购总监）        🔴 阻塞仓库收货  2h 前 ┐  ← 一条 = 一个动作，点了直接进单据档案的动作态
│ ├ 01A 齐套 54%，缺 3 项长周期件（PM）  🟠 影响 11-13 交期 ┤
│ ┤ TX26001 质保金 ¥300,000 到期前 60 天（商务）🟠 
│ 右侧：⌘K 搜编号 · 我的项目 4 个（轨道缩略）
└──────────────────────────────────────────────────┘
```

- **数据源已有一半**：`GET /workbench/me` 的 `counts` + `notification` + `task`；缺一个**统一排序接口**（§5）。
- 14 个数字格 → **0 个**：数字只在"该我干"时出现，`0` 的项目**不占位**（与 §8.1「空值不占位」同一条口径）。

### 3.3 件档案（最该有、今天完全没有的一张页）

```
TX26001-01A-01-01-00-00  定制底板   [已发布 V1]   自制件 → 现改判 外协件
──────────────────────────────────────────────────────────────
轨道：设计✅ → 采购⏸ → 制造🔄外协中 → 装配— → 发运— → 现场— → 售后—
关键：数量 3 件 · 图版 V1（当前）· 需求 #17（待采购）· 外协 WX26002（约定回厂 11-08）
卡点：外协件未回厂，装配 01A 齐套率卡在 54%（缺此件 3 件）
──────────────────────────────────────────────────────────────
[结构] 父 TX26001-01A-01-00-00-00 ｜ 子 无 ｜ 材料 板材 Q235 2.0mm ×3（MI26003 已领）
[单据] PO26034 / GR26017 / WX26002 / PR26005 …（每行可点进单据档案）
[时间线] 09-28 工艺改判自制→外协（ECN CR26002）→ 09-30 发布冻结 → 10-02 外协发出（照片 2）…
[证据] 图纸 V1 [缩略图] · 外协发出照 · 回厂检验照
```

**为什么这张页价值最高**：它同时回答 §1 的 #1（卡点）、#3（哪个件还没到）、#4（按哪版图干）、#7（这台设备/这个件的全部历史），
而且**数据今天全都有**（`purchase_request.part_no`、`bom_item`、`prod_task.drawing_no+drawing_version`、`shipment_item.ref`、`site_issue.drawing_no/item_no`、`audit_log`）——
**只是从来没有一个地方把它们按"件"串起来**。

### 3.4 驾驶舱（00 卷 #6，gm 现在登录后什么都没有）

一屏四块，全部复用现成接口，**不需要三期成本模型也能做**：

| 块 | 内容 | 数据源 |
|---|---|---|
| 在手订单 | 阶段分布（线索/成交待立项/执行中/交付中/质保）+ 金额（`project:amount` 才有） | `GET /projects` |
| 交付风险 | 交期临期/超期 × 齐套率 <70% × 长周期件在途 | `deadline.scan_due` + `kitting/projects` |
| 卡点榜 | 每个项目"当前卡在哪个部门、卡几天、谁手上" | 新增 `rail` 接口（§5） |
| 售后与质保 | 60 天内到期质保、在保工单、备件低库存 | `acceptance/workbench` + `service/workbench` |

## 7. 护栏与双轨（避免改版改出回归）

1. **旧路由不删**：`ROUTE_REDIRECTS` 是永久兼容层（AGENTS §8.1）—— 新增对象层路由（`/items/{no}`、`/equipment/{p}/{e}`、`/docs/{type}/{ref}`）后，旧路径继续一跳到位。
2. **断言迁移不降级**：`e2e:ui` 里凡是断言"某台首屏有某动作"的，改版后**必须换成断言新骨架**，不许直接删（删一条要在本文记一行原因）。
3. **新护栏**（每条都要注入反例自证能红）：
   - `OBJ-图号/物料号必须可点进件档案`（静态：出现 `drawing_no`/`item_no`/`part_no` 渲染处必须有 `Link to=/items/`）
   - `SHELL-每台页签≤4`（静态，读 `configs/tabs.ts` 注册表计数）
   - `SHELL-无三层导航`（静态：一个页面里 `Tabs` 嵌套 ≤1）
   - `VIS-数字卡不占首屏`（ui：首屏内 `Statistic` 数量 ≤3 且不含值为 0 的卡）
   - `COPY-无内部口径上屏`（**升级现有护栏**：不再要求「卷 §」与 `>` 同行 —— 改为按 JSX 元素切分子树后扫**多行 children 文本**；先用 §2.2 那两处真违规当反例，确认它现在能红）
   - `TABLE-fixed列不遮内容`（ui：`scrollWidth ≤ clientWidth` **且** fixed 列左边界不压住相邻单元格文本）
4. **棘轮基线重置**：`inline style` 基线按新骨架重新起算（当前 850；改版期允许临时上升，R3 结束前必须 ≤400）。
