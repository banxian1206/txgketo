## 0. 四条设计主线

| # | 主线 | 在数据模型里的体现 |
|---|---|---|
| 1 | **编号即归属** | 自制/定制件**必须**带 `project_no`，标准件**必须为 NULL** —— 一条 CHECK 同时解决"串项"与"跨项目复用" |
| 2 | **图号 = 物料号** | `item.item_no` 用图号作主键，**不需要**图号↔物料号映射表 |
| 3 | **状态由单据推导** | 不存人工状态字段；"待采购/在途/已入库"由采购单、到货单、入库流水算出来（见 `04` §1） |
| 4 | **两个 BOM 合成一份** | `bom_item.bom_source` 区分【设计 BOM】与【材料 BOM】，合起来才是设备的完整 BOM |

## 1. 总览

```
project（唯一根 · TX{YY}{NNN}）
 ├─ customer / contact / payment_term / attachment      商务
 ├─ project_member                                       团队
 └─ equipment（01A / 01B）                               设备
      └─ drawing（图号 · 4 组层次码）→ drawing_version（V1/V2）
           └─ bom_item（设计 BOM + 材料 BOM）
                └─ item（物品：自制 / 定制 / 外协 / 标准件）
                     ├─ 标准件 → std_class（标准库三层：类别→品类→型号）
                     ├─ 采购链 → purchase_request → purchase_order → goods_receipt
                     ├─ 库存链 → warehouse_location / stock_item / stock_move / material_issue
                     ├─ 制造链 → prod_order → prod_task → prod_acceptance
                     ├─ 外协链 → outsource_task
                     └─ 装配链 → kitting_snapshot → assembly_record
      └─ shipment（发货指令 → 按结构生成发运清单 → 逐项勾已发 → 装车）
           └─ site_*（勘测 / 到货验收 / 每日汇报）
                └─ acceptance（客户验收 → 自动进质保）
                     └─ service_order（售后工单）
```

                    source · site_address · is_retrofit · product_type · required_cycle · required_capacity
                    est_amount · expect_sign_date · competitor · related_project_no · risk_note · sales_id
                    period_start · period_end · amount · amount_tax_incl
                    contract_no_customer · warranty_months · warranty_amount · penalty_note
                    acceptance_standard · designated_brand · delivery_mode · site_condition · is_batch_delivery
                    tech_agreement_frozen · stage · close_reason · close_note
                    warranty_start · warranty_end · pm_id · created_by
payment_term    ✅  id · project_no · seq · node_name · percent · amount · expect_date · condition
                    received_amount · received_date             ← 回款跟踪
attachment      ✅  id · project_no · category · filename · stored_path · size · version · is_frozen
project_member  ⬜  id · project_no · user_id · project_role（项目内角色，与组织岗位无关）

**★ `project` 是唯一根**：商机、订单、合同、项目是同一行记录的不同阶段（`stage` 推进），
`project_no` 在建商机那一刻就发好，一生不变。

### 2.1 新建线索 —— 必填项

| # | 字段 | 字段名 | 说明 |
|---|---|---|---|
| 0 | **商机编号** | `project_no` | 系统自动 `TX{YY}{NNN}`，不用人填 |
| 1 | **客户名称** | `customer_id` | 从客户库选或新建 |
| 2 | **项目名称** | `project_name` | 如「美的 110 寸 TV 总装线」 |
| 3 | **客户方联系人** | `contact` | 姓名 / 职务 / 电话 / 微信 —— **可多个**（技术对接人、采购、决策人） |
| 4 | **接收到的资料** | `received_docs` + `attachment` | 按**资料清单勾选** + 上传：客户需求书 / 产品图纸 / 节拍产能要求 / 现场照片 / 招标文件 / 样品照片 / 其他 |
| 5 | **项目描述** | `project_desc` | 客户要解决什么问题、大概要什么设备 |
| 6 | **项目截止时间** | `deadline` | 客户要求什么时候交付 |
| 7 | **项目方式** | `deal_mode` | 投标 / 直接签合同 |

### 2.2 建议补充（选填，但有则更好）

| 字段 | 字段名 | 为什么建议记 |
|---|---|---|
| **线索来源** | `source` | 老客户复购 / 客户询价 / 展会 / 转介绍 / 招标平台 / 销售拜访 —— 用来算哪条渠道成单率高 |
| **项目地点（客户工厂地址）** | `site_address` | 直接决定现场安装成本与差旅，深圳/惠州双工厂调度要看它 |
| **是否旧线改造** | `is_retrofit` | 改造项目要停客户产线，现场窗口紧、风险高，**立项时标红** |
| **客户产品类型** | `product_type` | 如 110 寸 TV、变频空调 — 方案同事最需要的三个数之一 |
| **要求节拍** | `required_cycle` | 如 25 秒/台 |
| **要求产能** | `required_capacity` | 如 120 台/天 |
| **预计金额** | `est_amount` | 线索阶段先有个数，方便排产与资金预测 |
| **预计签单时间** | `expect_sign_date` | 销售漏斗 |
| **竞争情况** | `competitor` | 主要对手是谁、客户是否已有既定供应商 |
| **关联历史项目** | `related_project_no` | 同一客户 / 同类型设备以前做过没有 —— **设计复用与成本估算的关键** |
| **风险标记** | `risk_note` | 付款条件差 / 交期极紧 / 客户信誉不明 |
| **履约保证金** | `performance_deposit` + `performance_deposit_return_date` + `performance_deposit_returned` | ★ **我们交给对方的钱**，履约完成后收回（与质保金方向相反）。选填；要跟踪金额 / 预计退还日期 / 是否已退 |
| **销售负责人** | `sales_id` | 谁在跟 |

### 2.3 成交登记 —— 必填项

| # | 字段 | 字段名 | 说明 |
|---|---|---|---|
| 1 | **项目周期** | `period_start` / `period_end` | 开始 / 结束（系统按此排里程碑） |
| 2 | **合同金额** | `amount` / `amount_tax_incl` | 含税 / 不含税口径 |
| 3 | **付款方式** | `payment_term` | 节点明细：预付款 / 发货款 / 验收款 / 质保金 —— 各**比例% + 金额 + 预计日期 + 触发条件** |

### 2.4 成交登记 —— 建议补充

| 字段 | 字段名 | 为什么 |
|---|---|---|
| **技术协议（上传并冻结）** | `tech_agreement_frozen` + `attachment.is_frozen` | ★ = 设计基线；验收时的“裁判” |
| **质保期** | `warranty_months` | 验收确认 → 自动算出**质保到期日**（见 §10） |
| **质保金** | `warranty_amount` | ★ **客户从货款里扣留、质保期满才付给我们的那笔钱**（不是我们交出去的）。**由付款节点里名字含「质保」的那一条自动带出**，不单独填 |
| **交期与违约条款** | `penalty_note` | 逾期罚则 → 决定项目计划的风险等级 |
| **验收标准** | `acceptance_standard` | 对照技术协议：节拍 / 良率 / 连续运行时长 / 培训要求 |
| **甲方指定品牌或供应商** | `designated_brand` | 非标项目常见 —— **指定件不能换供应商、不能合并采购** |
| **交货方式与地点** | `delivery_mode` | 厂内提货 / 送货到厂 / 到场安装 |
| **客户现场接收条件** | `site_condition` | 水电气、地坪、通道、进场时间窗 |
| **是否分批交付** | `is_batch_delivery` | 大件必然分批 —— 先约定批次数量与时间点 |

### 2.5 关闭订单

必填**关闭原因** `close_reason`：价格 / 交期 / 技术不满足 / 客户取消 / 对手中标 / 其他（+ `close_note` 备注）—— 用于复盘报价策略。

## 3. 工程域（T04–T06）

```sql
drawing         ⬜  drawing_no PK · scheme（MECH_LEVEL / ELEC_SEQ）· project_no · std_code
                    equip_no · line_no · l1..l4（4 组层次码）· seq_no（电气图序）
                    parent_drawing_no（由层次码推导）· title · kind · current_version · status
drawing_version ⬜  id · drawing_no · version（V1/V2…）· file_id · change_reason
                    submitted_by/at · reviewed_by/at · published_by/at · is_current
bom_item        ⬜  id · parent_type · parent_ref · child_item_no
                    bom_source（DESIGN / MATERIAL）★ · qty · unit · source_type · pos_no · remark
item            ⬜  item_no PK（图号 或 标准库码）· display_name · source_type
                    （自制件 / 定制件 / 外协件 / 标准件）· project_no · std_class_code
                    spec(JSONB) · spec_text · unit · brand · mfr_model · is_active
std_category    ⬜  code(2) PK · name                                -- YL 原材料 / BZ 外购标准件 …
std_class       ⬜  code PK · name · category_code · spec_template(JSONB)
spec_field      ⬜  class_code · code · name · type · unit · required   -- 品类规格模板的字段定义
```

**关键约束**

| # | 约束 | 挡住的问题 |
|---|---|---|
| 1 | `item` 归属 CHECK：非标件必带 `project_no`，标准件必须为 NULL | 非标串项 / 标准件重复建码 |
| 2 | `(std_class_code, spec_text, brand)` 唯一 | 同规格建两个码，采购重复下单 |
| 3 | `drawing_version (drawing_no) where is_current` 唯一 | 两个"当前有效版本"，车间做错图 |
| 4 | `drawing.parent_drawing_no` 必须存在 | 孤儿图纸、BOM 断链 |
| 5 | `equipment (project_no, equip_no)` 唯一 | `01A` 撞号 |

## 4. 采购域（T08）

```sql
purchase_request       ⬜  请购/需求（进"待采购池"）
                           id · project_no · equip_no · item_no · qty · need_date
                           status（待判定 / 库存可用 / 待采购 / 已合并 / 已下单 / 已取消）
                           source（常规 / 长周期）★ 长周期不走合并、立项即下单
                           merged_into_order_id（被合并进了哪张采购单）
purchase_order         ⬜  id · po_no · supplier_id · order_date · expect_date · status · amount
                           is_merged · merge_note（合并了哪些项目/小组的需求）
purchase_order_line    ⬜  id · po_id · item_no · qty · price · amount · received_qty
supplier               ⬜  id · code · name · contact · phone · payment_terms · is_active
goods_receipt          ⬜  id · po_id / po_line_id · receipt_no · receipt_date
                           deliver_to（仓库 / 直发现场）★ · project_no（直发时必填）
                           status（到货待检 / 已检合格 / 不合格）· inspected_by · inspected_at
                           photos(JSONB)                              ← 逐条勾选 + 拍照
```

**★ 两条通道**：
- **长周期件**（如 ABB 机器人，2 个月）→ 立项阶段**直接下单**，不进合并池
- **常规件** → 查仓库 → 缺的进待采购池 → **累计合并**（跨小组/跨设备/按品类规格）→ 生成采购单

## 5. 库存域（T07 · 第一个真实试用点）

```sql
warehouse_location ⬜  id · warehouse_code（深圳 / 惠州）· location_code（A-03-12）· name
stock_item         ⬜  id · item_no · location_id · qty_on_hand · qty_locked（占用）
                       unique (item_no, location_id)
stock_move         ⬜  id · item_no · move_type（入库 / 出库 / 移库 / 盘点 / 退料）
                       qty · from_location · to_location · ref_type · ref_id · operator_id · moved_at
material_issue     ⬜  领料单（车间排产时自动生成）
                       id · issue_no · project_no · equip_no · item_no · qty
                       status（待备料 / 已备料 / 已领走）· issued_by · issued_at · photos
```

**仓库三件事 = 三个动作**（客户口述）
1. **来料检验验收**：系统按采购单的预计到货时间**自动列出"明日到货清单"** → 逐条勾选 + 逐条拍照
2. **入库**：拍标签（或选库位）→ 写入 `stock_move` + `stock_item`
3. **领料**：排产即**自动生成领料单** → 仓库备料 → 车间领走

## 13. 状态推导（不存人工状态字段）★

**所有"这个件现在什么状态"都由单据推导**，状态定义与判定依据见 `04` §1（22 个状态）。

```
有 bom_item            → BOM 需求
跑库存后无货且无采购单  → 待采购
有 purchase_order      → 已下单
有供应商发货记录        → 在途
有 goods_receipt       → 到货待检
有入库 stock_move      → 已入库
有 material_issue      → 已领料
有 prod_task           → 已派工 → 制造中（未到 plan_end）
有 prod_acceptance(合格) → 已转运装配区
有 kitting_snapshot(100%) → 已齐套
有 assembly_record     → 已装配
有 shipment_item(已勾发) → 已发货/装车
有 site_receipt        → 已到现场
                        → 已安装 → 已验收 → 售后
```

**为什么不存状态字段**：手工维护的状态会过期、会骗人；推导出来的永远和事实一致。
**性能**：30 人规模，实时推导毫无压力；如需加速，用物化视图（`fact_bom_line`）刷新。
