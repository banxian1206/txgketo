# 全角色工作台重新设计（2026-10-07）

用户扩大范围：整个工作台需要重新设计。以 docs/21 的全系统理解、docs/22 的真实角色交接证据、docs/19 的已确认首段规格为依据；不把现有部门台结构视作必须保留的产品规则。

## 1. 当前成果与边界

已制作独立可操作样稿：`frontend/public/design-lab/workspace/index.html`。覆盖19种职责视角，含销售执行/经理、PM、专业经理、设计组员、工程总监、工艺、采购执行/审批、仓管、车间/质检、装配/厂内调试、发运、现场负责人、调试工程师、售后、财务、经营负责人、系统管理员。部分职责暂合并用于对照，不意味着正式角色权限已合并。

样稿可切角色、切处理/跟踪/记录、查找事项、展开依据与交接。使用示例数据，不调用 API、不执行任命或审批，也不模拟真实业务完成。正式工作台尚未替换。本次是全工作台重构的第一版整体基准，不是全站实施完成。

## 2. 首页的组织原则

- 标题说明当前职责；一句话说明主要目标，范围说明区分本人、共享与部门跟踪。
- 主体优先承载要处理的真实对象；少量待办数字放在对应分区，不再同时重复铺一排指标和说明。
- 三种内容语义：需要处理、协作跟踪、工作记录。它们作为样稿统一基准，正式实施时以各角色任务验证，不把三个空分区机械套给所有人。
- 每条事项有对象、状态和具体动作；展开后说明为什么到这里、当前责任、处理依据、下一步与实际交接去向。
- 全局动作与行内动作分开：销售新建商机是全局动作；指定PM、审单、验收批次放在具体事项上，不在页头重复当前行的提交按钮。
- 项目、设备、零件协作可读；相关记录不称为本人待办，不新增身份代看功能。
- 手机单列、事项动作可触达；桌面左侧只保留稳定导航，业务流不再占据每个角色的首页主菜单。

## 3. 角色核心与事项

| 职责 | 处理事项优先呈现 | 首要工作依据 / 交接 |
|---|---|---|
| 销售执行 | 客户跟进、成交资料、回款节点 | 客户需求与约定；成交后销售经理安排PM |
| 销售经理 | 未指定PM成交项目、商务启动协调 | 成交约定与候选PM；实际PM组织立项 |
| PM | 启动准备、节点延误、现场协调 | 项目约定、团队与设备；实际专业任务接收人 |
| 专业经理 | 专业工作安排、本级审核 | 主任务与本轮评审；执行人或工程总监 |
| 设计组员 | 退回修改、本人进行中任务 | 原任务与对象、版本及意见；原评审单下一轮 |
| 工程总监 | 本人终审、工程改版依据 | 本轮版本与影响；有效发布和实际下游结果 |
| 工艺 | 有效机械依据后的材料BOM与来源判定 | 已发布机械结构；工程评审与制造来源 |
| 采购执行 | 下单需求、供方交期、叫车 | 需求/库存/价格；采购价格审批或发运 |
| 采购经理/总监 | 轮到本级价格审批、供方异常协调 | 单行历史价格；串行下一审核级 |
| 仓管 | 本批验收、入库、领料交接 | 对应供方/采购单行/数量；实物接收方 |
| 车间/质检 | 下发、返工、验收合格后转运 | 有效图纸与验收履历；实际转运接收方 |
| 装配/厂内调试 | 设备装配缺口、厂内调试结果 | 实物与有效设计；PM安排发运 |
| 发运 | 核对清单、装车、实际发出 | PM指令与车辆；同份清单交现场 |
| 现场负责人 | 来货差异、安装日报、调试申请 | 实发/实到与照片；实际协调/调试责任 |
| 调试工程师 | 被派现场、到场与调试反馈 | 任务与有效技术依据；现场与PM组织验收 |
| 售后 | 本人维修与处理签字；受理/派工另分 | 故障、设备历史、备件；实际关单结果 |
| 财务 | 应收实收、应付已付核对 | 合同/采购/登记凭证；商务或采购协调 |
| 经营负责人 | 交付风险、责任缺口、质量协调 | 项目真实影响；具体责任人落实 |
| 管理员 | 账号、组织、权限、配置 | 配置与日志；本人角色核对业务入口 |

## 4. 正式实施的地基

现有销售台 `/sales/board` 对普通经理仍按本人 sales_id 筛选，仅总监/超管看全量；输出缺少PM归属。不能只把页面写成“经理未指定PM队列”就声称实现。正式实施须先明确授权的管理范围，再补只读队列字段和任命入口，保持审计与原有权限。已确认“销售经理负责指定PM”不等于已确认跨部门全量数据权限。

任务归属与对象可提交集合、改版按工程归属部门裁决、部分实物数量与齐套、调试本人日报、缺损异常闭环，都按 docs/21 §13.4 的证据与依赖处理。UI不凭空添加审批、自动补采或验收拦截。

## 5. 分段实施顺序

1. 销售执行/经理→PM：本人跟进、成交交接、未指定PM、指定实际PM、PM启动。
2. 工程经理→组员→总监：安排任务、有效依据、退回、提交、本级审核与发布。
3. 采购→仓库→制造/装配：同单行同批次数量、供方、质量与实物交接。
4. 发运→现场→调试→验收→售后：实发/实到、异常处理、被派任务与关闭结果。
5. 财务/经营/系统管理及全站手机导航、消息与深链收尾。

每段完成正常、退回/异常、等待前置、空队列四类真实角色场景，才替换下一段；首页计数、队列、消息与对象必须同源。

浏览器逐一切换19种职责，核对标题与非空事项；销售经理指定PM事项展开显示依据与交接去向。样稿脚本语法检查通过。后续记录桌面/手机截图和交互检查，不把样稿验证称为正式角色权限或全链验收。

## 7. 正式实施首批（2026-10-07）

正式销售与PM台已迁移职责模式：保留统一WorkbenchPage和原深链，去重复指标，增加职责范围、查找与直接事项。销售组员与经理待办分开；本人跟进、回款、协作记录各自清楚。PM启动仅实际本人归属；执行风险可直达项目概览，参与项目明确关系。接口新增实际客户/销售/PM与is_owner，不改数据模型或既有读范围；回款节点不再截断前50条。

销售经理首次指定PM采用专用入口，校验角色/权限/现有范围/阶段/未分配及启用PM候选，锁项目后复用原任命审计。范围尚待确认，沿本人销售归属范围落地，不能宣称公司未分配项目已全部覆盖。更换已有PM不从首次指定入口处理。

同时修正390手机顶栏：保留检索图标、消息、头像与退出，收起长说明；职责事项改为单列，名称/依据不被固定宽列挤成竖字。表格协作记录保留横向滚动。
