# 前后端一致性审计报告

> 项目：同兴高科项目管理系统（txgketo）
> 日期：2026-09-22　|　范围：后端 FastAPI 全量路由/字段 vs 前端 React（PC + /m）
> 方法：脚本化差集（路由 × 前端调用 × 字段）＋ 人工核实关键页面
> 结论：**主链 UI 齐全，字段基本无遗漏**；发现 **7 处"后端有接口、前端无入口"**、**1 个前端用法错误（图片放大链接坏）**、**3 处与新规则相关的 UX 缺口**

---

## 一、审计方法

1. **路由级差集**：抽取后端 220 条路由（`router prefix + 装饰器路径`）与前端全部 `api.*()` 调用（含泛型、模板字符串），双向求差。
2. **字面量存在性**：把每条后端路径转成正则，在前端**全部源码**里搜索（覆盖 `fetchFileBlob`、`<img>`、手拼 URL、动态拼接等非 `api.get` 的用法）。
3. **导出函数引用**：统计 `api/client.ts` 的 206 个导出函数里，哪些未被任何页面/组件引用（= 没有 UI 入口）。
4. **字段级核对**：把后端表单模型（`ProjectCreateIn`/`DealIn`/`PaymentTermIn`/`ContactIn`/`ProjectUpdateIn`）的字段逐个在前端搜。
5. **关键页面精读**：设计、仓库、制造、发运、标准库、编号规则、提交评审弹窗、移动端验收。

## 三、后端有接口、前端没有入口（功能缺失）

| # | 功能 | 后端接口 | 前端现状 | 影响 |
|---|---|---|---|---|
| 1 | **标准库物料编辑** | `PATCH /library/items/{item_no}` | `Library.tsx` 只有"新建 + 列表"，`client.ts` 无 `updateItem` | 建错的品牌/型号/规格/单位无法修改，只能弃用重建 |
| 2 | **程序文件下载/查看** | `GET /programs/{id}/file` | 设计页只把文件名当**纯文本**显示（`EquipmentDesign.tsx:940`），无下载/预览 | 车间/售后拿不到已发布的 PLC 程序文件 | 
| 3 | **图纸文件查看（PC）** | `GET /drawings/{no}/file` | 仅手机端"物料详情"用了一次（`m/AcceptM.tsx` 的 `file_url`）；PC 设计页无入口 | PC 上无法查看某张图的附件（只能看到"已传文件"标签） |
| 4 | **车间看图** | `GET /manufacturing/drawings/{project}/{equip}` | 制造页只显示"图纸 {图号} {版本}"文字（`Manufacturing.tsx`），无查看 | 车间下发后无法照着图纸加工 |
| 5 | **发运清单"摆放位置照片"** | `POST /shipping/items/{item_id}/place` | `client.ts` 有 `setItemPlacePhotos`，但**无任何页面引用** | 装车时"哪件货放在哪"的留痕功能用不上 |
| 6 | **到货验收照片查看** | `GET /goods-receipts/{id}/photos/{idx}` | 手机端验收会**上传**照片（`m/AcceptM.tsx:108`），但 PC/移动端**都不展示** | 仓库/采购拍了照却没人能回看 |
| 7 | **图号解析 / 组装工具** | `GET /numbering/drawing/parse`、`/compose` | `NumberRules.tsx` 只读规则列表 | 可能是有意的运维接口，**待确认**是否需要做进页面 |

### 另有"client 函数有、但无 UI"的次要项（低优先）

| 接口 | client 函数 | 说明 |
|---|---|---|
| `DELETE /projects/{}/members/{}` | `removeMember` | 立项后无法移除团队成员 |

## 四、前端"接了但会失败"（用法错误）

### 4.1 图片"看大图"链接是坏的 ⚠️

- **现象**：发运/制造页的大图入口用原生 `<a href={shipPhotoUrl(ph)} target="_blank">`（`Shipping.tsx:517/540/553`、`Manufacturing.tsx:578/597`）。
- **两个问题**：
  1. `shipPhotoUrl`/`mfgPhotoUrl` 返回的是 `/shipping/photos?token=...`（`client.ts:2665`、`2402`），**没有 `/api/v1` 前缀**，而 Vite 只代理 `/api` → 打开是前端首页/404；
  2. 该接口需要 `Authorization: Bearer` 头，浏览器直接跳转**不会带**这个头 → 即使前缀对了也会 401。
- **对比**：同一页的**缩略图**走 `AuthedImage → fetchFileBlob → axios(baseURL=/api/v1 + 拦截器加 token)`，是正常的。
- **建议**：大图也走 `fetchFileBlob` + 弹层预览，或给这些 `<a>` 加 `/api/v1` 且改为带 token 的 blob 打开。

## 五、与新规则相关的前后端 UX 一致性

| 规则 | 后端 | 前端 | 结论 |
|---|---|---|---|
| **附件必填** | 提交评审时图纸/程序无文件 → 400 | 弹窗**已显示**"已传文件 / 未传文件"标签（`SubmitReviewModal.tsx`），但**允许勾选未传文件的项并提交** | 信息有了，未做前置拦截；建议禁选并提示 |
| **总装图强制随批发布** | 本批发布设备内容时总装图必须一起发布 → 400 | 弹窗把总装图**当作普通草稿图**列出，无"总装图"标识、不默认勾选 | 用户容易漏勾被 400；建议默认勾选 + 标注"父级/总装图" |
| **超额验收硬拦** | 到货数量 > 未到数量 → 400 | PC/移动验收弹窗**默认数量=未到数量**（与规则一致），但输入框无 `max` 上限 | 行为基本一致；建议加 `max` 与提示文案 |
| **同型设备复制设计** | 发布后自动复制给 01B | 立项页有"同型再来一台"入口（`InitiationEditors.tsx`）；设计页按设备加载，会自动显示复制后的图 | ✅ 一致 |
