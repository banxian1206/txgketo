## 2. ★ N20 [P3·唯一残留] 采购池标签文案写死，把「现场缺件」显示成「退货重采」

```tsx
// frontend/src/features/purchase/Page.tsx:321-329
render: (v, r) =>
  ['退货重采', '现场缺件', '现场破损'].includes(v) ? (
    <>
      <Tag color="orange">退货重采</Tag>        // ★ 条件泛化了，文案还是硬编码
      {r.origin_po_no && <div>原 {r.origin_po_no}</div>}
    </>
  ) : ( ... )
```

**现象**：一条 `source='现场缺件'` 的补采需求，在采购池「来源」列会显示成**橙色「退货重采」标签**（配上正确的「原 PO26026」溯源）。

**为何要修**：这比修复前更误导 —— 修之前走 else 分支显示的是**正确的**灰标签「现场缺件」，只是没有溯源；现在溯源有了，名字却错了。采购员会以为是仓库验收不合格退的货，而不是现场缺的料 —— **两者的补采紧迫度和责任方不一样**（仓库不合格要找供应商协商、现场缺件可能是运输/清点问题）。

**修法**：1 行，与 Drawer 保持一致
```tsx
<Tag color="orange">{v}</Tag>
```
**全库扫描确认这是唯一残留**：`grep -rn ">退货重采<" src/` 只命中 `Page.tsx:323` 一处；Drawer 已是 `{l.source}`。
