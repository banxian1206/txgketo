# UI 页面统一标准 · 工作台母板

2026-10-08｜客户确认：以后新建或调整 UI 页面，先读本标准，再设计和实现。

## 1. 适用范围与优先级

本标准适用于本项目所有后续工作台、列表、详情、表单、弹窗和手机页面，包括交互样机。视觉基准为采购工作台样机 `/design-lab/proposals/purchase-workbench.html`，但不得照搬其采购业务字段、示例权限或模拟数据。

**同一角色层级只改变职责、动作和数据范围，不另起一套字体、颜色、壳和间距。** 每次UI施工先读本文件，再读该领域业务规格；先复用公共组件，缺少的公共能力先扩展组件。

与旧视觉文档冲突的字体/配色/公共壳按本标准执行；业务规则按客户最新确认及领域文档，不由视觉规范决定。没有冲突的旧可访问性、品牌、表单、审批、手机规范继续有效。存量正式页面逐域迁移，不声称本轮已全站改造完成。

## 2. 唯一视觉参数源

样机参数文件：`frontend/public/design-lab/shared/ui-tokens.css`。后续样机引用这份文件，不复制另一份变量；正式React页面在现有 `theme/` 与 `components/ds` 中映射这些值，不引入新UI库、不复制样机多层render脚本。既有别名与旧组件逐步迁移，同名状态只保留一个映射。

### 字体与层级

字体：`-apple-system, BlinkMacSystemFont, 'PingFang SC', 'Microsoft YaHei', sans-serif`。使用系统中文字体，不加载外网字体。控件继承字体；数字金额用等宽数字（tabular-nums），编号需要时用既有等宽字体。

| 用途 | 字号 | 字重 / 行高 |
|---|---:|---|
| 普通正文与表单内容 | 14px | 400 / 1.55 |
| 表格正文与字段值 | 13px | 400；重点600 / 1.55 |
| 次要说明、表头、元数据 | 12px | 400；表头500 / 1.55 |
| 日期、轻量徽标与辅助标注 | 11px | 400 / 1.55；仅辅助内容，不用于主操作 |
| 一级页签、摘要标题 | 14px | 选中/重点600–650 |
| 列表区标题 | 14px | 600 |
| 详情与表单标题 | 18px | 600 / 1.4 |
| 页面主标题（需要时） | 24px | 650 / 1.3 |
| 问候标题 | 23px；手机21px | 650 / 1.3 |

10px只用于顶部未读徽标和快捷键提示，不用于正文。主次通过层级与留白表达，不靠全篇加粗；不要每页另定一套字号。

| 普通正文 | #1b2941 | — |

| 页面 / 内容纸面 | — | #f4f7fc / #ffffff |
| 选中 / 悬停 | — | #edf3ff / #f5f8fd |

状态采用圆点＋文字，单据左摘要、右详情、表格、弹窗使用同一口径；不能某页待处理红、另一页橙。选中行背景独立为浅蓝，不表示异常或完成。复合状态优先异常，其次待办阶段：在途但逾期→红；合格但待入库→橙；已叫车但待装车→橙。角色名称与普通分类不是警告，不标橙。正式代码传业务枚举映射，禁止按文字猜状态；当前样机的中文兼容映射见purchase-status.js。

Logo使用品牌既有素材：浅底正色深灰字＋橙色图形，深底反白；不把品牌橙色替换成主按钮蓝。图标使用既有图标系统或同风格SVG线图标，不用emoji或字符冒充系统图标。

## 3. 公共尺寸与布局

- 桌面内容最大宽1440px，左右32px；窄屏左右16px。容器min-width:0，正文避免固定最小宽撑破页面。
- 摘要栏固定300px，右侧minmax(0,1fr)，间隔16px；不能在不同分类来回变宽。采购品类、任务摘要、单据摘要使用同一规格。反馈页可用正文＋右侧300px辅助栏。
- 区块与导航到正文间距16px。详情标题/正文内距20px 22px；手机17px。列表头16px 18px。用4/8/12/16/24/32的间距梯度，禁止随机逐页调数值。
- 公共纸面圆角13px、控件8–10px；轻量胶囊仅用于分类选择及问候快捷入口。边框1px，正文不堆阴影卡片；浮层才用柔和阴影。
- 桌面普通按钮/输入36px，顶部搜索消息账号38px；手机主要触控至少40px。输入/按钮同组同高。
- 一级导航48px高，最小宽108px（手机90px）；二级分类38px左右、文字12px、浅灰轨道＋白色选中块，视觉弱于一级导航。一级计数20px高、最小24px宽，0不隐藏。
- 表格单元格默认15px内距、文字13px；表头11px 15px、文字12px。业务允许时一行摘要，品牌规格/来源为次行；长标题换行、表格自身横滚，不撑动整页。大列表必须复用正式分页/虚拟化策略，不为追求一屏强缩字号。

## 4. 工作台壳与页面结构

公共顺序：品牌与全局搜索/消息/账号 → 公告（有才显示）→ 问候与陪伴区 → 一级导航 → 二级分类（需要时）→ 摘要/详情或表单正文。各一级页签共用同一头部尺寸，切页签时不隐藏或改变问候高度。

- 一级基准：今日待办 / 任务 / 项目 / 问题。正式角色是否有某功能以业务权限为准，不因为母板展示便自动授权。
- 今日待办是任务中需优先处理的子集，每件事出现一次；任务分类随职责改变；项目保留全局进展；问题分我提交的和提交给我的。
- 先看摘要，再同页查看细节及处理；左栏概要应足以定位问题，右侧给来源、负责人、数量、状态、处理入口。避免无必要的三级页面跳转。
- 同一数据集合统一计数口径：记录数不混设备数量；问题按记录去重。七阶段任务徽标当前含历史分类记录，正式落地时统一服务端任务集合口径，不把同一对象的多个阶段重复累加。
- 员工/经理/总监同一骨架；经理/总监增加审批和职责范围，个人收件仍按接收人，不能无说明扩大到团队。
- 问候快捷按钮是导航，点击进入对应处理页面，不直接提交、审批或默认打开业务操作弹窗。

## 5. 交互与状态要求

1. 一级/二级导航与选中对象进入URL，刷新保持位置；保留已有来源和查询参数。过期对象安全回落。滚动条占位固定，页签切换不调用推动整页的scrollIntoView。
2. 首屏只显示完成初始化的最终布局，不先闪旧HTML。实际应用用一致加载骨架/稳定容器；失败必须能重试，不能永久隐藏正文。
3. 必须设计正常、有数据、空列表、处理中、成功、失败、长内容、窄屏状态。空态给可执行下一步，不能只画一张装饰图。
4. 表单字段有label、必填与明确错误；用户输入切区不丢失；正式antd分区keepMounted。提交失败定位首个错误字段；不要重复全屏弹窗报错。
5. 主操作一处明确，次操作低权重；disabled原因可理解。保存草稿与提交审批区分，待审批不可伪装已下单。
6. 可键盘操作、焦点可见；图标按钮有可读名称；当前导航有aria-current/aria-selected。红绿同时配文字，不只靠颜色。
7. 附件可预览/移除，图片尺寸预留不推动布局；小宠物不遮挡工作，尊重减少动画设置；AI入口避让底部操作栏。
8. 查询控件与状态显示统一；未知状态中性显示且保留原文，禁止编造成功。样机数据与真实数据明确区分。

## 6. 每次UI任务的施工与验收

施工前：读本文件→读业务域文档→找现有公共组件和token→确认数据/权限/状态口径→实现。默认遵循这套标准，不需要每次再问用户颜色字号。用户明确新决定时先回写标准，再施工。

交付前：检查布局及状态一致性、导航刷新、长内容和手机；运行与改动相称的测试。正式React变更按AGENTS要求build/tsc及相关护栏；纯文档不冒称运行UI回归。无浏览器实测须明确指出。

每次汇报必须说明：改了哪个入口、用户如何验收、期望看到什么、已完成及未完成的验证。通过静态/DOM桩不等于实际视觉通过。

本标准建立状态：采购样机已引用公共token，主要颜色和壳已实现；部分既有字号/控件仍需视觉补验，正式全站尚未迁移。以后以本标准作为新页面目标，不以任一残留旧页面为标准。

## 7. 母板接线前必须核对业务数据

视觉标准不等于功能需求或数据来源。正式页面套用母板前，逐项对照模型、接口、角色范围及当前真实记录；采购参考 `docs/30-采购母板与现有系统差异核对.md`。区分“模型有/接口未返回/当前记录为空/口径未定义”。不为保留样机示例添加字段或虚构数字，不用通知替代问题处理，不用创建人替代执行负责人。缺数据有明确空值显示；缺能力隐藏或标未启用；业务变更独立审批、审计及测试。迁移时保留模板未画出的真实必要入口和权限。

## 8. 登录页适配（2026-10-08，按客户最新决定简化）

正式登录页 `/login` 全终端为居中的单列白色表单，浅灰蓝背景，表单内只有正色TXAM Logo、登录标题、账号、密码、记住密码、密码帮助和登录按钮。删除品牌侧栏、生命周期说明和额外介绍文案。采用本标准字体与配色，24px标题、14px控件、13px标签、12px辅助文字；表单宽400px、容器圆角13px、内距32px（480px以下24px），页面外距16px。输入框和主按钮统一40px、圆角8px。认证逻辑不变。
