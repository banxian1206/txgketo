## 0. 先读三条

### 0.1 一个号贯穿始终

```
商机 TX26001 = 订单 TX26001 = 合同 TX26001 = 项目 TX26001
   └─ 设备 01A / 01B
        └─ 图号 TX26001-01A-02-01-00-00（图号 = 自制/定制/外协件的物料号）
```

系统里**只有一个根对象 `project`**，`stage` 字段推进阶段；`project_no` 在建商机那一刻发号，一生不变。

### 0.2 与 02 卷的差异（★ 实现已跑出文档，以本表为准）

| 02 卷写的 | 实际实现 |
|---|---|
| `purchase_order` / `purchase_order_line` 两张表 | **没有建表**。采购单 = `purchase_request.po_no` 相同的行**归拢出的视图**（`GET /purchase/orders`），金额/供应商/状态都在需求行上 |
| `purchase_request.status` 含「待判定/库存可用/已合并/已下单」 | 实际枚举见 §S3（客户口径重做过，含「在途/部分到货/现场待验收」等） |
| `packing_list` 装箱单 | **已废弃**，改为 `shipment_item` 发运清单（散件发运不装箱，逐项勾「已发」） |
| `cost_entry` / `fact_bom_line` / `data_scope` / `file` | **未建**（三期：成本毛利、驾驶舱） |
| `drawing_version.reviewed_by` 单级审核 | 改为**两级审核 + 评审单**（`review_ticket` / `review_action` / `design_release`），版本表字段保留兼容 |
| `site_receipt` 独立清点 | 保留，但**逐项结果落在 `shipment_item.check_*`**，`site_receipt` 存汇总结论 |

## S0 商机登记 → 成交 / 关闭

**谁做**：销售工程师（建商机）、商务专员（成交登记）、销售总监（取舍）
**入口**：`pages/Projects.tsx`（商机列表）· `pages/ProjectDetail.tsx` · 商务部台 `SalesWorkbench.tsx`
**编号**：`TX{YY}{seq:03}`（如 `TX26001`），全局按年取号，建商机即发

### 动作与接口

| # | 动作 | 接口 | 结果 |
|---|---|---|---|
| 1 | 新建商机（必填 8 项 + 联系人≥1） | `POST /projects` | `project.stage = 线索` |
| 2 | 上传资料包（方案/报价/合同/技术协议/客户资料） | `POST /projects/{no}/attachments` | `attachment` 一行 |
| 3 | 编辑商机（每次改动落 `旧值→新值`） | `PATCH /projects/{no}` | `audit_log` |
| 4 | **成交登记** | `POST /projects/{no}/deal` | `stage → 成交待立项` |
| 5 | **关闭订单**（二选一） | `POST /projects/{no}/close` | `stage → 已关闭` |

## S1 立项（项目组全体会议）

**谁做**：项目经理 + 项目组全体
**入口**：`pages/Initiation.tsx` · `pages/ProjectDetail.tsx`
**要做三件事**：① 统一理解（团队任命）② 任务分配（01A/02A… 各是什么设备）③ 长周期采购立项即下单
**编号**：设备号 `{seq:02}{letter}`（项目内取号，`01A`/`01B`）· 任务号 `TK{YY}{seq:03}`（**全局按年**）

### 动作与接口

| # | 动作 | 接口 |
|---|---|---|
| 1 | 任命项目团队 | `POST /projects/{no}/members` |
| 2 | 建设备清单（01A 升降机 / 02A 点胶机…） | `POST /projects/{no}/equipment` |
| 3 | 定节点计划（时间段） | `POST /projects/{no}/milestones` |
| 4 | 登记长周期件 → **立项即下单** | `POST /projects/{no}/purchase-requests` + `/order` |
| 5 | **生成任务**（设备×专业 + 采购） | `POST /projects/{no}/generate-tasks` |

### 字段：`project_member`（项目团队）

| 字段 | 说明 |
|---|---|
| `project_no` + `project_role` | **唯一约束**：一个项目一个角色只能一个人 |
| `user_id` | 谁 |
| `project_role` | 枚举 `PROJECT_ROLES`：项目经理 / 技术负责人 / 机械负责人 / 电气负责人 / 程序负责人 / 工艺负责人 / 采购负责人 / 生产负责人 / 装配负责人 / 测试负责人 / 现场负责人 / 售后负责人 |
| `remark` | |

> ★ 项目内角色与组织岗位**无关**：同一个人在不同项目可以是不同角色。
> ★ 任命「项目经理」时必须同步写 `project.pm_id`。

## S2 工程设计（两个工作节点 → 一份完整 BOM）

**谁做**：各设计小组（机械/电气/程序）+ 工艺部；经理一级审、总监二级审
**入口**：`pages/EquipmentDesign.tsx`（设计工作面）· `pages/Reviews.tsx` · `pages/MyTasks.tsx`
**编号**：机械图 `{project}-{equip}-{l1}-{l2}-{l3}-{l4}`（组合式，不取序列）· 电气单机图 `{project}-{equip}-90-{seq:03}` · 电气线体图 `{project}-{line}-{seq:03}` · 评审单 `RV{YY}{seq:03}` · 发布批次 `RL{YY}{seq:03}`

### 流程

```
① 设计小组：建图纸树 → 上传草稿(V1) → 挂设计 BOM(标准件/定制件) → 判定自制/外协
② 工艺部：看设计 BOM → 生成材料 BOM(原材料) → 改判定制件
③ 勾选提交评审（任务级一张单，可多轮）
      ↓ 组员提交
   待经理审 ──退回──► 已退回（回草稿，可再提交）
      ↓ 通过（经理自提/空缺 → 自动跳过并留痕）
   待总监审 ──退回──► 已退回
      ↓ 通过
   已发布 = ★冻结（写一条 design_release）→ 按本批内容自动进采购池
```

**★ 两条产品硬规则**（客户 2026-09-22 确认）：
1. **附件必填**：图纸/程序没上传文件，不允许提交评审（校验 `ver.file_path`）
2. **总装图强制随批发布**：`{p}-{equip}-00-00-00-00` 必须在勾选内或已发布

### 字段：`drawing`（图纸）

| 字段 | 类型 | 说明 |
|---|---|---|
| `drawing_no` | str(48) PK | 图号 = **自制/定制/外协件的物料号**（不建映射表） |
| `scheme` | str(24) | `MECH_LEVEL`（机械层次码） / `ELEC_SEQ`（电气序号） |

## S3 采购

**谁做**：采购员（下单/取消/换供应商/协商）、采购主管
**入口**：`pages/PurchaseWorkbench.tsx`（采购池 / 采购单 / 验收不合格 / 退换记录 / 入库记录 / 到货跟踪 / 价格参考 六页签）
**编号**：采购单 `PO{YY}{seq:03}`（合并下单共用一个号）· 到货单 `GR{YY}{seq:03}` · 供应商 `S{seq:04}`（**都全局按年/全局取号**）

### ★ 采购状态线（客户口径，别再改回去）

```
待采购（在采购池） --合并/单条下单--> 在途（等货，可分多批）
      --仓库验收合格--> 待入库 --仓库入库--> 已入库
      --直发客户现场--> 现场待验收 --现场清点齐--> 现场已验收
      --仓库验收不合格--> 不合格 --采购协商--> 换货（原供应商补发，回「在途」）
                                          / 退货（新建一条「待采购」回池重买）
```

### ★ 采购只有三个动作

**下单 · 取消（未到的部分）· 更改供应商**；验收不合格由采购跟供应商协商 **换货 / 退货**。
采购侧**不登记到货/发货**，状态被仓库推着变（`_recalc_request_status()` 由到货单反推）。

### 两条通道

| 通道 | 谁触发 | 走不走合并 |
|---|---|---|
| **长周期件**（ABB 机器人，2 个月周期不备货） | S1 立项即下单 | ❌ 直接下，状态 `在途` + 自动发号 |
| **常规件** | 设计/工艺**发布**自动进池；或设备面手动「生成采购需求」；或手工申请 | ✅ 查仓库 → 净需求 → 累计合并（跨小组/跨设备/按品类规格）→ 一张采购单 |

净需求 = **已冻结的** BOM 展开 −（库存 + 本项目已领走）− 在跑需求（`OPEN_STATUS` 含「在途」，不会算漏重复采购）；**幂等**，重复点不重复进池。

## S4 仓库（★ 只有两个动作：验收 · 入库；加一个领料）

**谁做**：仓库专职操作岗（**不给每个工人开账号**）
**入口**：`pages/Warehouse.tsx`（PC）· `/m/warehouse`（手机验收动线：看图→拍照→合格/不合格→入库）· `/m/issues`（领料）
**编号**：领料单 `MI{YY}{seq:03}`（全局按年）
**权限**：验收/入库/领料 → `warehouse:edit`

### ★ 到货单状态机

```
（下单时按 deliver_to 分岔）
公司仓库  → 到货 → 待入库? 不，先验收：
   验收合格 → 待入库 → 入库 → 已入库
   验收不合格 → 不合格 → 采购协商 → 已换货（原供应商补发，需求回「在途」）
                                  → 已退货（★ 新建一条「待采购」需求回池重买）
直发客户现场 → ★ 下单即建「现场待验收」单（现场立即可清点）
   现场清点「齐」→ 现场已验收（需求同步转「现场已验收」）
```

### ★ 必经顺序（不能跳、不能抄近路）

```
① PM 勾选本次要发的设备（待发 10 台，本次只发 01A、02A）→ 下达发货指令
        ↓ status = 已指令
② 系统按【设备结构】自动生成发运清单（组件→子组件→零件 + 标准件/原材料，数量按结构连乘）
        ↓ status = 发货中（★ 真实语义是「清单确认中」，不代表车在路上）
③ 发货人逐项勾「已发」+ 拍照（勾大组件 = 整棵子树都发；结构外的说明书/备件/工具手动补充）
④ 装车 {vehicle, driver, plate_no, photos}      ↓ status = 已装车
⑤ 发运（在途）                                   ↓ status = 在途  ★ 此后清单只读
⑥ 登记到货                                       ↓ status = 已到货
⑦ 现场逐项清点 → 签收                             ↓ status = 已签收
```

### ★ 五条硬口径（吃过亏，别改回去）

1. **发货与收货一致**：勾「已发」的就是实际发出的；现场**只清点本批已勾「已发」的项**（未发的留后续批次，不要求也不接受清点）
2. **0 项已发 = 不能装车、不能发运、不能清点**（三处共用 `_shipped_count`）；**部分已发（如 50/100）= 软提示确认**（P-08）
3. **清单锁死线 = 「发运」**：`已指令 / 发货中 / 已装车` 都能补勾、补补充项（装车后改主意有出口）；一旦 `在途` 就只读（否则现场清点依据不成立）
4. **`depart` 只接受 `已装车`**
5. ⚠ 系统**没有批次取消/作废**口 —— 任何「往前不能退」的硬拦都必须往前挪到还能改的地方拦，否则会造出永久死批次
