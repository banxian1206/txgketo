# 前端交互设计规范（重构施工用）

> 2026-09-22 ｜ 配套 `前端重构方案-2026-09-22.md` 使用
> 读者：实施重构的人。每条规范 = **反例（实测问题）→ 规范 → 落地组件**，施工时直接照抄。
> 业务前提（03 卷 / AGENTS）：手机是主要终端；用户是仓库/车间/现场人员；动线 = **清单 + 勾选 + 拍照**；不做扫码。

## 0. 六条设计原则

| # | 原则 | 反例（实测） | 正例（系统里已有的，保留推广） |
|---|---|---|---|
| 1 | **数字驱动待办**：打开即知"几件事、先干哪个" | 某些页面只有空列表，无聚合计数 | 工作台四张数字卡（待验收/待入库/…）+ 点击下钻 |
| 2 | **一个动作一屏三步**：不跳页、不翻菜单 | 仓库验收要点：卡片→弹窗→拍照→合格→入库（已是三步 ✅） | `/m/accept/:id` 验收动线 |
| 3 | **反馈必须落在视图上**，toast 只是辅助 | P-20：生成领料单 400，toast 2 秒消失、页面零变化 | 列表页提交成功后行状态即时变色/计数刷新 |
| 4 | **一致性即易学性**：同名动作同范式 | "验收"在仓库=Modal+Radio、制造=Modal+Radio 但预填失效、现场=另一套 | 固化为唯一 `ActionModal` 范式（§2.1） |
| 5 | **禁用必须给解释** | P-21：未勾选时「合并下单」变灰无 Tooltip | `disabled` + `Tooltip`，或改为可点+提示"先勾选需求" |
| 6 | **入口可见性**：用户自然会看的地方必须有入口 | P-04：PC 现场页顶部画着"勘测→汇报→申请调试"动线，却没有一个创建按钮 | 空态 Empty 附带主按钮（§2.5） |

## 1. 信息架构与导航

### 1.1 PC（AppLayout）

```
侧栏三分组（现状保留）：
  工作台    我的工作台 / 商务部 / 项目经理 / 工程部 / 采购 / 仓库 / 车间   ← 首屏唯一入口
  业务      我的任务 · 商机/项目 · 设计评审 · 改版 · 制造 · 装配 · 发运 · 现场 · 验收 · 售后 · 供应商
  基础数据   标准库 · 编号规则 · 用户与权限                                ← 按权限显隐

详情页：
  · 层级 ≥2 用面包屑（项目 → 设备设计面），替代散落的「← 返回项目」文字链
  · 列表 → 详情优先用 Drawer（上下文不丢：采购单详情模式保留）
  · 独立大页面仅用于：新建商机、立项、设计面、工作台（需要整屏专注的）

**规则**：任何业务动作，用户路径 = 工作台数字卡（或侧栏）→ 业务页 → 动作。**不允许超过 3 层**。

  （角色显隐逻辑已有，收敛只动壳不动业务 —— 阶段二实施，需产品确认，见 §7）
```

**登录分流**：`<820px` 登录进 `/m`（现状保留，勿改）。

## 2. 五个核心交互范式（施工契约）

### 2.1 动作弹窗 `AppModal` —— 全站 60 个 Modal 收敛到这一个范式

**反例**：P-03 `setFieldsValue` 预填丢失（45 处 `destroyOnClose` 各写各的时序）；P-12 领料用原生 `window.prompt`。

**契约**：

```tsx
// components/AppModal.tsx —— 时序固定：挂载表单 → 预填 → 展示
<AppModal
  title={`验收 · ${row.display_name}`}        // 动作名 · 对象，永远告诉用户在对谁操作
  subtitle={`采购单 ${row.po_no} · 订购 ${row.qty}，已到 ${row.received}`}  // 单据上下文
  open={open}
  form={form}
  initialValues={{ result: '合格', date: dayjs() }}   // ★ 打开即生效（根治 P-03）
  fields={...}                                     // 字段描述（§2.3 字段组件）
  danger={result === '不合格'}                     // ok 按钮随结论变红
  submit={async (v) => { ... }}                    // 由 useSubmit 包裹，reject 统一 catch
  onSuccess={(res) => { message.success(res.hint); reload(); }}  // ★ toast + 视图刷新成对出现
/>
```

**硬规则**：
1. 预填值必须在**首次渲染即可见**（实现：`forceRender` 或打开回调里 `setFieldsValue`，测试用例锁住）
2. 提交中按钮 loading，**防重复提交**
3. 关闭即销毁字段（`destroyOnHidden`），下次打开回到 `initialValues`
4. 禁止 `window.prompt/confirm`，一律 AppModal / Popconfirm

### 2.2 提交与校验 `useSubmit`

**反例**：P-09 空提交时 `validateFields()` reject 未捕获（控制台 `pageerror: Object`）、Form.List 空数组校验不触发。

**契约**：

```ts
const submit = useSubmit(form, {
  request: (v) => inspectPurchase(id, v),
  success: (res) => `验收合格 → ${res.receipt_no} 待入库`,
  onSuccess: () => reload(),          // ★ 必填：状态变化要落回视图（原则 3）
})
// <Button onClick={submit.run}>  内部已含：validate → catch → message.error(errMsg(e)) → loading
```

**校验时机**：
- 字段级：`blur` 即校验**已填**字段（不打断未填的）
- 提交：全量标红 + 自动滚动到第一个错误
- **列表型必填**（联系人、付款节点）：字段为空时就在列表标题旁行内提示「+ 至少添加 1 个」，**不等提交**（antd Form.List 空数组不触发 rules，必须显式兜底）

### 2.4 列表双壳（PC Table / 移动 List 共用数据 hook）

```
features/warehouse/hooks.ts   useWarehouseBoard() + useInspect() + useStore()   ← 唯一一份
features/warehouse/Page.tsx      PC 壳：Table + 页签 + 行内操作          <120 行

```

**行内操作链接规范**：主操作用 `Button(primary, sm)`，次操作 `a`；**操作列固定右侧**；隐藏的行操作要么不渲染、要么渲染但 🔒+Tooltip（§4）。

### 2.5 三态（空 / 加载 / 错误）

```tsx
<EmptyState
  title="还没出图"
  hint="按设备已发布图纸展开：自制件排产、外协件外发"
  action={{ label: '新增条目', onClick: openAdd }}   // ★ 空态必须有可点的下一步（原则 6）
/>
```
- **空态**：一句话说明 + **主按钮**（反例 P-04：现场页空列表连按钮都没有；反例 P-20：失败只在 toast）
- **加载**：表格骨架 / 按钮 loading；>300ms 才显示 loading，防闪烁
- **错误**：行内错误条 + 重试按钮（见 §3 分级文案）

## 2.6 登录与会话 · 记住密码（2026-09-23 新增）

**功能**：登录页提供「记住密码，本机下次自动登录」勾选项 —— 目标是**被登出后不需要重新输入**。

| 场景 | 行为 |
|---|---|
| 勾选 + 登录成功 | 凭据（账号+密码）存本机单键 `txgk_credential`（XOR 盐 + Base64 **弱混淆，非加密**） |
| **被动失效（401 被踢 / session 过期）** | 跳登录页 → **自动重新登录** → 回原目标页，**全程无需重输**（核心诉求） |
| **主动点「退出登录」** | **清除凭据** —— 退出必须是真退出，否则点退出又被自动登回，按钮形同虚设 |
| 凭据失效（改密 / 停用） | 自动清理凭据 + warning 提示回表单，**不循环重试** |
| 想换账号 | 自动登录态提供「使用其他账号」→ 清凭据 + 回表单 |

**安全边界（诚实声明）**：密码必须存（登录接口要求）；混淆仅防直接窥视，**不提供加密强度** —— 安全边界 = 能读本机 localStorage 的人已能做其他操作；系统为内网私有部署，且**仅在用户主动勾选时**才存。

**UI 约束**：勾选项在密码框与登录按钮之间；自动登录态显示 Spin +「正在自动登录…」+「使用其他账号」。

**e2e**：`REMEMBER-保存凭据` / `REMEMBER-被动自动登录`（401 模拟）/ `REMEMBER-主动登出清凭据` 三断言（`e2e/ui.mjs`）。

## 3. 错误与反馈分级

**反例**：P-06 填错项目号，页面裸显 `Request failed with status code 500`。

在 `api/http.ts` 拦截器统一（阶段一 1.2）：

| 场景 | 文案 | 呈现 | 后续动作 |
|---|---|---|---|
| 400 业务 | **透传后端原话**（"父级图号不存在：…"） | toast error | 弹窗保持打开，用户可改 |
| 403 | 无权限执行此操作（需要 `warehouse:edit`），请联系管理员 | toast error | 无 |
| 404 | 对象不存在或已被处理 | toast warning | **自动刷新列表** |
| 500 | 系统异常，请重试；若持续请截图反馈 | toast error | 弹窗保持打开 |
| 断网/超时 | 网络不可用（现场弱网）——离线动作进队列 | 顶部持久条 | §5 离线 |

**成功反馈公式**：`toast（一句话结果）+ 视图变化（计数/状态/新行）`，二者缺一不可。
例：`已入库：GR26005 → 深圳仓 A-01-01` + 待入库卡片数字 1→0 + 该行从待办消失。

**必填校验反馈**：行内红字（antd explain），**不使用**纯 toast 代替标红。

## 4. 权限的两级表达

| 级别 | 场景 | 表达 |
|---|---|---|
| **不可见** | 越权功能/菜单（仓库看不到采购台） | 不渲染（现状已正确，9/9 实测通过 ✅ 保持） |
| **可见但无权** | 同事的单据我点不了 / 金额我看不到 | 控件保留 + 🔒 或 `—` + **Tooltip 说明缺什么** |

**金额特例**（P-17）：`—` 必须能区分两种含义
```tsx
{amount == null ? <Tooltip title="你没有查看金额的权限"><span>—</span></Tooltip>
 : amount === 0   ? <span>¥0</span>
 : <span>¥{fmt(amount)}</span>}
```
（后端 `scrub_money` 返回 null = 无权限；0 = 真为 0，前端要按此区分。）

**伪装态**（X-Impersonate）：顶栏橙色横幅保持现状（醒目、防误操作）。

## 5. 移动端专项

1. **触控**：主操作按钮 ≥44px 高、吸底或首屏可见；行内链接在移动端换成整卡可点
2. **动线固定为「清单 → 勾选 → 拍照 → 提交」四拍**（03 卷）：所有 `/m/*` 动作页照此拼装（现有 Warehouse/Accept/Shipping 已符合，保持）
3. **拍照**：`capture="environment"` 直调相机；缩略图 + 删除；弱网先本地压缩（已有 `utils/image.ts` ✅）
4. **离线**（阶段三）：动作提交失败 → 按钮变「待同步 ⏳」+ 首页队列数字；**绝不静默丢弃**
5. **与 PC 对等**：同一业务动作两端必须都有入口（原则 6 的双端版，根治 P-04）
