## 3. 本轮发现并修复的真缺陷（1 条）

### D1 ★ 设计面标准件/材料 BOM 未按设备收口（同型 01B 出现后两台互串）

| | |
|---|---|
| **现象** | 建出同型第二台 01B 后，**01A 和 01B 的设计面互相列出对方的标准件/材料**：`标准件 4 / 材料 4`（各自本应 2/2）；BOM 列表里同时出现 `TX26001-01A-…` 与 `TX26001-01B-…` 的行 |
| **影响** | 设计面"标准件/材料"清单与计数**翻倍/串项**，误导设计、工艺与采购；`parts_without_material` 等完整性判断建立在错误集合上 |
| **根因** | `backend/app/api/routes/engineering.py::get_design_tree`：`bom_rows = select(BomItem).where(BomItem.project_no == project_no)` —— **只按项目取，没按设备**。此前只有一台设备带 BOM 时被掩盖，同型第二台一出现就暴露 |
| **修法** | `bom_rows` 改为 `BomItem.parent_ref.in_(本设备图纸集合 ∪ {设备号})`；`design_overview` 的 `refs/mats` 同步按 `in_tree` 收口 |
| **证据** | 修前 API：01A `std_items:4/materials:4`，std parents 含 `…01B…`；修后：01A `2/2` 仅 `…01A…`，01B `2/2` 仅 `…01B…`；浏览器 01A/01B 均显示 `标准件 2 · 材料 2` |
| **护栏** | `backend/tests/test_design_parts_and_issue_idempotency.py::test_design_tree_bom_rows_are_scoped_to_equipment`（**注入旧代码 FAIL、修后 PASS** 已自证能红） |
| **提交** | `aba6b74 fix(设计): 设计面 BOM 行按设备收口` |

## 6. 脚手架问题（非产品问题，列出来免得误判）

1. **antd 空态/度量行**：`table tbody tr` 的 `.first()` 会命中隐藏的 `ant-table-measure-row`（无按钮）→ 循环第一次就退出（已改为按内容 `filter`）。
2. **手机端按钮/tab 在视口外**：需先 `scrollIntoViewIfNeeded` 再点（如 `/m/site` 的「每日汇报」tab）。
3. **antd 2 个中文字自动加空格**：按钮文本是「处理 / 审批 / 入库」，正则要写 `/处\s*理/` 这类；写死的 `/处理/` 匹配不到（我因此多跑了一轮退货）。
4. **手机验收卡片选择器**：`/m/warehouse` 第一张卡点掉后列表刷新，第二轮会点到陈旧卡片（本轮仍靠后补脚本补齐入库）。
5. **制造「开工」循环**：同一行反复取 `.first()`，第一次开工后该行不再有"开工"按钮 → 后续迭代超时（靠后补脚本补齐）。

> 这些都不影响产品结论；下一次若把这些脚本固化成护栏，建议顺手按上面 5 点加固。
