## 2. 问题清单

### 🔴 P-01【阻断】新设备第一张图纸无法通过 UI 创建 —— 设计主线被卡死

- **模块**：S2 工程设计（`/projects/{p}/design/{e}`）
- **复现**：新建商机 TX26003 → 成交 → 立项（建设备 01A）→ 打开设计面 → 点「+ 新增条目」→ 父级唯一选项「📦 01A 测试升降机总装图 · 还没建，新增后自动创建」→ 填名称 → 新增
- **实际**：弹窗报错 **`父级图号不存在：TX26003-01A-00-00-00-00`**，弹窗不关、图建不出来；「挂在哪个下面」是必填且没有其他选项 → **无法绕过**
- **期望**：如 UI 文案所说"新增后自动创建"总装图（后端 `add_drawing` 注释也写着"第一次出图时自动建"）
- **根因线索**：`backend/app/api/routes/engineering.py:301` —— `if body.parent_drawing_no and body.parent_drawing_no not in used: 400`；总装图只在 `parent_drawing_no` **为空**时自动创建，但前端必填校验强制传了这个还没存在的图号
- **影响**：所有**新立项设备**的出图入口全断。存量演示项目 TX26001/TX26002 的图纸是种子脚本造的，所以此前未暴露
- **证据**：`dump/b4b-uploaded.txt`、`shots/diag-add*.png`

### 🔴 P-02【阻断】"辅料/办公用品"类采购需求永远无法验收（404 死循环）

- **模块**：S3 采购 → S4 仓库
- **复现**：采购工作台 → 手工申请（归属=辅料，物料=方通×5）→ 进池 → 合并下单（PO26005）→ 仓库页 → 该行点「验收」→ 提交
- **实际**：浏览器抓包 `POST /api/v1/projects/null/purchase-requests/6/inspect → HTTP 404`，前端提示"**采购需求不存在**"，**弹窗永远关不上**，重试多少次都一样
- **根因**：手工申请的辅料/办公用品/其他 `project_no` 为空，验收接口路径要拼 `/projects/{project_no}/…`，前端直接拼出 `null`
- **附带**：验收弹窗头部「归属」一栏显示空白
- **影响**：辅料采购走完下单后**在仓库端卡死**，货到没法验收、没法入库
- **证据**：`dump/diag-inspect.txt`、抓包记录（上方第②条）

### 🟠 P-03【严重】`destroyOnClose` 弹窗的默认值预填全部失效（通用型 bug）

- **模块**：全站弹窗（制造 / 装配 / 设计面）
- **复现（任一即可）**：
  1. 制造页 → 在制单点「验收」/「转运」→ 弹窗打开后"转运到"是空的（代码预填了"装配区"）
  2. 装配页 → 点「开始装配」→ "装配类型"预填"整机装配"丢失
  3. 设计面 → 「+ 新增条目」→ 父级预填丢失（加重 P-01）
- **实际**：页面 dump 出现 `请输入转运到` 校验失败；用户必须手动补选本该预好的默认值
- **根因线索**：代码模式为 `form.setFieldsValue({...})` **先于** Modal 打开/字段挂载执行，且 Modal `destroyOnClose` + Form `preserve={false}` 关闭即清值。受影响：`Manufacturing.tsx:145-150`（5 种动作）、`Assembly.tsx` 开始装配、`EquipmentDesign.tsx` 新增条目/挂原材料
- **影响**：不是崩溃，但每个动作弹窗都要多点两下，且"必填"报错会让用户以为自己漏填
- **证据**：`dump/b7-after-transfer.txt`（"请输入转运到"）

### 🟠 P-04【严重】PC 端现场安装页**没有创建入口**，勘测/日报/问题/申请调试全靠手机端

- **模块**：S8 现场（`/site`）
- **实际**：PC `/site` 选项目后，四个页签（来货清点/每日汇报/现场问题/申请调试/勘测）**全部只有列表和状态操作**（转变更/闭环/已到现场/开始调试…），**没有一个"新建"按钮**；创建 API（`site/survey`、`site/daily`、`site/issues`、`requestCommission`）只在移动端 `SiteM.tsx` 里被调用
- **矛盾点**：页面顶部写着完整动线引导"勘测 → 来货清点 → 每日汇报 → 申请调试"，但 PC 用户按引导**无处下手**
- **对照 AGENTS §8.5**：典型"做完了但找不到入口"
- **期望**：要么 PC 补创建入口，要么页面显著提示"请用手机端 /m/site 录入"
- **证据**：`dump/b9-site.txt`（页签计数全 0 且无按钮）、`Site.tsx` 源码 grep

### 🟠 P-05【严重】申请客户验收**没有"调试完成"前置校验**（流程门禁缺失）

- **模块**：S10 验收
- **复现**：验收台 →「申请客户验收」→ 项目号填 **TX26001**（该项目 `site_commission` 表为空，从未做过现场调试）→ 申请
- **实际**：提示"已申请客户验收"，验收单成功创建（DB：`acceptance id=2, status=待验收`），并给销售角色发了通知
- **期望**：文档 `docs/00-方案-业务与建设.md` S9 明确"**调试完成 → 申请客户验收**"，应拦截
- **根因线索**：`services/acceptance.py:48 apply_acceptance()` 只查"是否已在申请中"，无调试完成前置判断
- **影响**：跳过 S9 直接进 S10，业务顺序失控且污染下游通知
- **附带**：弹窗"项目号"是**手填 Input**（见 P-14）

### 🟠 P-07【严重】项目详情接口金额未分档，无权限用户可看到合同金额

- **模块**：权限（06 卷 F 步"金额分档"）
- **复现**：`wh1`（角色 WAREHOUSE，只有 `project:view`，**无 `project:amount`**）登录 → `GET /api/v1/projects/TX26001`
- **实际**：返回 **`amount = 1680000.0`**（168 万合同额）
- **对照**：列表接口 `GET /projects` 做了分档（`project.py:179` 逐字段置 None）、`/projects/{no}/detail` 也做了（`:474 scrub_money`），**唯独 `GET /projects/{project_no}`（`project.py:188 get_project`）漏了** —— 函数参数直接 `_` 忽略 user
- **影响**：任何有项目查看权的低权限角色（仓库/车间/现场）都能看到项目金额，违背"金额分档"设计
- **证据**：API 对比记录（admin/buyer1 可见，wh1 也可见 = 泄漏）

### 🟠 P-08【严重】发运清单一项没勾（0/6），照样能装车、发运、清点、签收

- **模块**：S7 发运
- **复现**：下达指令 FH26002 → **不打开清单勾任何"已发"** → 直接「装车」→「发运」→「登记到货」→「现场清点」→ 提交
- **实际**：全链路畅通，最终状态 **`已签收`，发运进度始终 `0/6 项已发`**（dump 可见）；现场清点弹窗却列出 6 项全"到"
- **期望**：按 05 卷/AGENTS §8.1，散件发运要"逐项勾『已发』+ 拍照"，装车/发运前至少应警告或拦截"还有 6 项未勾"
- **影响**：清单形同虚设，"到/缺/损"清点结果与实际发货内容脱节，现场对不上单
- **证据**：`dump/b8-items.txt`、`dump/b8b-after-receipt.txt`（最终 0/6 已签收）

### 🟡 P-09【一般】列表型必填校验不触发 + 空提交抛未捕获异常

- **模块**：S0 商机 / 成交登记
- **复现**：
  1. 新建商机空表单直接点「建立商机」→ 只标红 6 个字段，**「至少要有一个客户方联系人」不提示**（联系人一行都没有时）
  2. 成交登记空提交 → 只标红 4 项，**「至少登记 1 个付款节点」不提示**
- **根因线索**：antd `Form.List` 在 `value.length === 0` 时其 `rules` 校验器不执行；同时 `form.validateFields()` 的 reject 没被 catch（`ProjectCreate.tsx:58` 等多处 `void submit()`），浏览器控制台抛 `pageerror: Object`
- **影响**：用户填完所有标红项、再点提交才会发现"还要加联系人/付款节点"，多一轮挫败；控制台脏异常
- **证据**：`shots/b1-empty-submit.png`（6 项标红）、`shots/b2-deal-validate*`、抓包 `pageerror {"message":"Object"}`

### 🟡 P-10【一般】已成交项目仍在列表显示"商机剩余 还剩 14 天"

- **模块**：S0 商机/项目列表
- **实际**：TX26001（执行中）、TX26002（**质保**）阶段下，`商机剩余` 列仍显示"还剩 14 天"（`deadline=2026-10-06`）
- **期望**：商机截止只对 `线索` 阶段有意义，成交后应显示"—"或隐藏，否则像"这单还没谈完"
- **证据**：`shots/b1-after-create.png`、`Projects.tsx:98-108`

### 🟡 P-11【一般】入库"库位"是手填文本，不联动库位主数据

- **模块**：S4 仓库
- **实际**：入库弹窗「入库库位」是自由 `Input`（placeholder "如 深圳仓 A-01-01"）；系统明明有库位主数据（`listLocations`，库里已有"深圳仓 A-01-01"）和「库位」管理页签
- **风险**：手打容易打出"深圳仓A0101"等变体 → 库存按字符串聚合，同一库位分裂成多条
- **对照**：必填校验本身生效（空提交提示"入库必须定库位" ✅）

### 🟡 P-12【一般】领料人用浏览器原生 `window.prompt` 输入

- **模块**：S4 仓库（`Warehouse.tsx:268`）
- **实际**：点「车间领走」弹的是**浏览器原生 prompt**（样式与其他 antd 弹窗完全割裂，手机端体验差，且 prompt 可被禁用）
- **期望**：与其他动作一致用 antd Modal（必填、可校验）

### 🟡 P-13【一般】PC 端与移动端功能不对称且无提示（同 P-04，验收侧）

- 验收「申请客户验收」的项目号、售后「报修」的项目号/设备号均为**手填 Input**（placeholder "如 TX26001"），没有项目下拉 → 填错一个字符就触发 P-06 的 500
- **期望**：改为 Select（数据源 `listProjects` 全站都在用）

### 🟡 P-14【一般】手工申请物料搜索无结果时，没有"去标准库新建"出口
