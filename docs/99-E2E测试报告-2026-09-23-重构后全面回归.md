## 3. 新发现问题

### 🔴 R2-01【S1 阻断】直发客户现场链路完全断链 —— 直发单是"死单"，无任何 UI 可推进

- **复现（全程 UI）**：手工申请（归属=项目 TX26010）→ 合并下单，收货地点选 **直发客户现场**（地址必填 ✅ 正常通过，PO26037 · 在途）→ **接下来两头都推不动**：
  1. 仓库「待验收」列表 **不含** PO26037（7 条全是公司仓库单）—— 无法做"登记到货"
  2. 现场「来货清点」`site/incoming?project_no=TX26010` = **空** —— 无从清点
- **根因链（代码证据）**：
  - `warehouse.py:567` 仓库待验收查询 `deliver_to == "公司仓库" OR NULL` —— **合理排除直发**（不进公司仓库）
  - `goods_receipt(现场待验收)` **只在 `_perform_inspect`（仓库验收动作）里创建**（`initiation.py:1102`）
  - `site/incoming` 只查 `goods_receipt.deliver_to=直发 AND status=现场待验收` —— GR 从未被创建 → 永远空
  - 全前端 `inspectPurchase` 调用点仅 **2 个**（PC 仓库页 + 移动验收页），两者数据源都**排除直发**；采购单详情对直发只有紫色 Tag、无任何按钮
- **旁证**：库中仅有的 2 条直发 GR（GR26011/GR26029 · 现场已验收）来自**种子脚本直插**——**UI 链路历史上从未走通过**，第一轮"未覆盖"掩盖了它
- **影响**：直发是 S7/S8 设计内主场景（收货地点下单时即定、AGENTS §8.1 直发流程）——**该场景上线即卡死**
- **建议修法（二选一，需产品确认口径）**：① 下单时（deliver_to=直发）直接建 `goods_receipt(现场待验收)`，现场立即可清点；② `site/incoming` 改查在途直发需求（不依赖 GR）。注意与 AGENTS「采购侧不登记到货」的口径对齐
- **证据**：`dump/r2d-direct-po.txt`、`dump/`（site 空）、API 三连查记录、`warehouse.py:567`、`initiation.py:1102`

### 🟡 R2-02【S3 一般】回款登记弹窗预填丢失 —— P-03 模式的回归漏网点

- **复现**：项目详情（TX26010）→ 付款节点点「登记回款」→ **「本次实收金额」为空**（原预期预填未收额）、日期是否预填同批丢失
- **源码定位**：`features/project/DetailPage.tsx` `openReceive()`：
  ```ts
  setReceiveTarget(...)        // 触发 Modal 打开
  receiveForm.setFieldsValue({ received_amount: unpaid, received_date: dayjs() })  // 字段尚未挂载 → 值被丢
  ```
  Modal 为 `destroyOnHidden + Form preserve={false}`（关闭即销毁），**setFieldsValue 在挂载前执行 = 值丢** —— 与已修复的 P-03 完全同根因；**这处是手写 open，第一轮修 P-03 时未纳入 AppModal 基座**
- **影响**：体验回退 + 用户易误填（有必填校验与超额拦截兜底，**无资金风险**——C2c/C2d 实测兜底有效）
- **修法**：该 Modal 改走 `AppModal + initialValues`（1.2 基座），或 setFieldsValue 移到 open 后的 `useEffect`
- **证据**：`dump/r2c-pay1`、C2b 断言原文、源码 159-163 行
