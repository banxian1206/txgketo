# 16 · ERP 历史数据导入方案（供应商 / 标准库 / 采购历史价）

> 状态：**✅ 已落地并实导（2026-10-06）**

## 1. 目标

把 ERP 里三样东西搬进本系统，**只搬数据、不搬编码规则**：

1. **供应商** ~808 家 → `supplier`
2. **标准库** ~28,579 条 → `std_category` / `std_class` / `item`
3. **采购历史价** ~74,000 条 → `supplier_quote`（`price_type=成交`，供「价格参考」用）

### 2.1 三类数据的匹配度

| 关系 | 结果 |

### 2.2 数据质量已知问题（导入时按规则处理）

- **同名同型号**：按（品类+名称+型号+品牌）去重会撞掉 **1,952 条**（924 组）→ 用 ERP 原编号做 1:1 匹配（见 §4 编码）。
- **价格离群**：152 种物料历史价差 ≥10 倍（多为单位口径不同，如「个」vs「1000PCS/包」）→ **保留不删**，导入报告里列出。
- **超长字段**：ERP 产品型号最长 500，本系统 `item.spec_text` 只有 255 → 截断（原文留在内部来源字段）。
- **供应商字段缺失**：银行/税号/邮箱/传真全空；账期列全 0 → 用「付款方式」。

### 4.2 标准库（类别 / 品类 / 物料）

**分类树**：ERP `物料` 路径 `一级->二级->三级` → 类别 = 二级、品类 = 三级。
- 2 级路径（如 `车间/仓库耗材类->生产用品类`）→ 类别 = 一级、品类 = 二级。
- 4 级路径（如 `标准化类->通用零件->链轮->链轮`）→ 类别 = 二级、品类 = 末级。
- 预计 **27 个类别 / ~139 个品类**。
- **合并复用**：品类名与本系统现有 17 个品类同名者（轴承/气缸/电机/减速机/机器人/伺服/链条/丝杆/导轨）直接复用现有品类码；其余新建。
- 新建类别/品类的代码：内置一份 **139 条的映射表**（`app/services/erp_legacy_map.py`，人工可调），拼音首字母大写、≤6 位、同类内去重。

**物料 `item`**：

| 目标字段 | 来源 | 规则 |
|---|---|---|
| `item_no` | — | **引擎**：`{类别码}-{品类码}-{seq:04}`（`STD_ITEM` 规则，按品类取流水） |
| `display_name` | 产品名称 | |
| `source_type` | — | `标准件` |
| `project_no` | — | `NULL`（满足 CHECK 约束） |
| `std_class_code` | 产品分类 | 映射后的品类 |
| `spec_text` | 产品型号 | 截断 255 |
| `mfr_model` | — | 留空（避免与 spec_text 重复） |
| `brand` | 品牌 | |
| `unit` | 单位 → 基本单位 → `件` | |
| `spec` | — | `NULL`（导入品类无规格模板，不走必填校验） |
| `is_active` | — | true |

**剔除**：产品编号以 `TX` 开头的（6,082 条）= 项目图号。

### 4.3 采购历史价 `supplier_quote`

解析：主单行（`采购编号` 非空且 ≠`【采购明细产品】`）取 采购编号 / 采购日期 / 供应商名称；其后明细行取 编号 / 数量 / 单价类字段，直到下一张主单。

| 目标字段 | 来源 | 规则 |
|---|---|---|
| `item_no` | 明细「编号」 | 经 `legacy_code` 映射到本系统物料；**查不到就跳过并记报告** |
| `supplier_id` | 主单「供应商名称」 | 按名称匹配 |
| `price` | 含税折后单价 → 优惠后单价 → 含税单价 → 单价 | 取第一个 > 0 |
| `tax_incl` | — | 用了含税列 = true；否则 false |
| `qty` | 数量 | 同键合并时求和 |
| `unit` | 单位 | |
| `price_type` | — | `成交` |
| `quote_date` | 采购日期 | Excel 序列号 → 日期 |
| `currency` | — | CNY |
| `project_no` | — | `NULL`（老项目不在本系统） |
| `source` | — | `ERP导入` |
| `remark` | 采购编号 · 设备名称 · 材料编号 | 溯源 |

**幂等键**：`(item_no, supplier_id, price, quote_date, source='ERP导入')`，重复导入不翻倍。

## 5. 导入脚本设计

新增 `backend/scripts/import_erp_legacy.py`（一次性迁移，不进业务接口）：

```
python -m scripts.import_erp_legacy                       # 预演（默认，不写库）
python -m scripts.import_erp_legacy --yes                 # 真写
python -m scripts.import_erp_legacy --yes --only suppliers
                        --only library --only prices        # 分阶段
python -m scripts.import_erp_legacy --dir /path/to/shuju   # 数据目录
```

特性：
- **默认预演**：只打印「将新建/合并/跳过/冲突」各多少 → 先给客户看数字。
- **分阶段、幂等**：供应商 → 品类/标准库 → 价格；任一阶段可单独重跑。
- **审计**：每阶段写一条汇总 `audit_log`（铁律 5），不写 10 万条。
- **报告**：结束时打印 + 落 `docs/shuju/import_report_<日期>.txt`：
  各类计数、跳过的 `TX` 清单、查不到的物料清单、离群价（≥10 倍差）清单。
- **事务**：按批（1000 条）提交，失败保留已完成批次并报行号。

### 5.1 读取 `.xls`

ERP 只导老版 `.xls`（BIFF8），本系统零依赖读取器只认 `.xlsx`/`.csv`。
- 脚本内 **可选依赖** `xlrd`：`try: import xlrd`，装了就直读 `.xls`；没装给出人话提示。
- `xlrd` **只装在开发机临时 venv，不写进 `requirements*.txt`**（不违反 AGENTS §3）。
- 同时支持 `.xlsx`/`.csv`（走 `services/excel_import.py` 的零依赖读取器），便于以后重导。

### 10.1 实导抓到并修掉的一个真 bug（值得记）

第一次实导后再跑一次，价格**多出 2,338 条**（56,316→58,654）。根因：
`supplier_quote.price` 是 `Numeric(14,2)`，入库把 `61.947` 四舍五入成 `61.95`；
而幂等键用的是**未取整**的 `61.947` → 重跑对不上 → 重复插入。
修法：金额统一 `_money()` 归一到 2 位（`Decimal + ROUND_HALF_UP`）后再做幂等键与入库。
修完重导 + 再重跑：**56,189 稳定不变**。
教训：**幂等键的字段类型与落库后的真实值必须一致**（`Numeric(14,2)` 会改数）。

## 11. 品类树收口 —— 以 ERP 为准（2026-10-06）

客户看到标准库侧栏里 13 个品类是 `0`（都是我们**本地设的种子品类**），拍板：
**「以 ERP 为准」** —— 本地那套品类不要了。

**删掉的本地种子品类（13 个 + 类别 `BZ` 外购标准件）：**

| 类别 | 删掉的品类 | 原因 |
|---|---|---|
| 原材料 | 方通 / 扁通 / 槽钢 / 板材 / 圆钢光圆 / 铝型材 | ERP 统归「原材料类→钢材/铁材/铝材/铜材…」 |
| 外购标准件 | 直线导轨 / 滚珠丝杆 / 电机 / 减速机 / 工业机器人 | ERP 归「导轨类 / 动力类」 |
| 电气件 | PLC / 视觉相机 | ERP 无对应物料 |

**收口后的状态（实测）：**

- `std_category` **19 个** / `std_class` **139 个** = **正是 ERP 映射表的全集**（`services/erp_legacy_map.py`）。
- **0 个空品类**（139 个每个都至少 1 条物料）。
- 保留的 4 个真正被复用的品类仍带规格模板：`SF 伺服` / `QG 气缸` / `LS 螺丝` / `ZCT 轴承`。

**做法（可重复）：**

1. `scripts/seed.py` 新增 `RETIRED_STD_CLASSES` / `RETIRED_STD_CATEGORIES`：
   - 不再创建这 13 个品类 / `BZ` 类别；
   - 若库里已存在且**没有物料引用**，seed 时顺手删掉（幂等，实测清掉 13 个）；
   - 同时把 `erp_legacy_map.py` 的类别/品类也落库 —— 保证「只跑 seed 不跑导入」的开发库也有完整品类树。
2. 回归脚本的测试基准品类跟着换成 ERP 品类（FT→GC、BC→YLLC、DJ→DLD、JSJ→DLJ、PLC→CPU；QG/SF/ZCT 不变），
   内部 key 保持不变以减少改动：`e2e_baseline` · `e2e_full_test` · `e2e_complex_test` · `seed_s0_s1` · `seed_base_data` ·
   `seed_demo_project` · `probe_bom_math` · `probe_n24_n25` · `multiproj_walkthrough`。
3. 标准库页默认落到**有物料的品类**（不再停在空种子上）。

> ⚠ 这些回归脚本**未在实导库上跑过**（跑 `e2e_baseline` 会复位、清掉导入的 2.8 万物料）；
