# 15 · 工作台队列化改造方案（台骨架统一）

> 起因（2026-10-05 客户实测）：「为什么每个工作台…的二级 tab 或三级 tab 不是统一的，而是每个页面都有不一样的？
> …我觉得这里也是需要重新设计一下的，因为现在也只是把内容摆出来了，根本没有设计可言。」
> **先讨论方案、别改动** → 讨论稿 §1–§4 经客户认可「照你的建议，开始动手」→ 落地记录 §5–§8。

## 1. 为什么会长成这样（三层原因，都是实测出来的）

**第 1 层｜上一轮做的是「分组」，不是「骨架统一」。**
R3-B 只解决了"页签太多"（把平铺 10 个收成 ≤4 组），**没规定"台长什么样"**：结论指标条放几个、流程条放哪、
体内用表格还是队列，全靠当时那个人（我）临场判断。

**第 2 层｜代码里并行着两套框架**（这是"看着就不是一家人"的直接原因）：

| 框架 | 出处 | 语义 | 用在哪 |
|---|---|---|---|
| `SectionNav` + `configs/sections.ts` | docs/14（较新） | 对象的**一个面** | 6 张详情/档案/表单页 + **仅 1 个台**（商务） |
| `WorkbenchTabs` + `configs/tabs.ts *_GROUPS` | docs/12 R3-B | 台的一类活儿 | **8 个台** + 评审/改版/任务/用户 4 个二级页 |

**第 3 层｜旧框架自己还退化成 3 种形态**：>4 项 → 组页签+Segmented；≤4 项 → 光 Segmented；≤1 项 → 连条都不画。

## 2. 先把"工作台是什么"定义下来

> **工作台的唯一职责 = 把"该我干的活"按流程顺序摊开，让我逐条处理完。**
> 它不是数据展示页，也不是报表页。

由此推出**固定四件套、顺序不许变**：

```
① 台头     PageHead：台名 + 一句话现状 + 台级动作（≤2 个）
② 结论条   Metrics：≤5 个，**只放"要动手的数"**，每个可点（to="?tab=xxx"）
③ 流程条   SectionNav（台与详情页同一个壳）：≤4 组；≤4 项时不分层
④ 体       队列类 → QueueBoard/QueueRow；台账类 → 表格
```

三条规格：

- **② 只放动作数**：身份、筛选器状态**不进结论条**（工程台的"工程部·机械·组员"、发运/现场的"选中的项目"都属上下文，进 `?` 或筛选器）。
- **体内两种语言的判定法（一句话）**：**这一行有没有唯一的"下一步动作"？**
  有 → 队列行（56px，右侧一个主按钮）；只是查/对账/要排序导出 → 表格。
  判定结果**声明在注册表**（`kind: 'queue' | 'ledger'`），护栏校验"声明与实现一致"。
- **空态统一 ds `Empty`**（说人话 + 下一步按钮），antd 默认灰插图全下线。

## 3. 一个壳、两种注册表（不合框架，只合壳）

| | 注册表 | 语义 | 用在 |
|---|---|---|---|
| `SectionNav` | `configs/sections.ts` | 对象的**面** | 详情 / 档案 / 表单（原样保留） |
| `WorkbenchPage`（新） | `configs/boards.ts` | 台的**一类活儿** | **9 个台全部** |

- `SectionNav` 扩成**共用底层**：加一个可选 `groups`（两层），不传时与旧行为**逐像素一致**（详情页零改动）。
- `WorkbenchPage` = 台骨架壳：自己管 `?tab=`、按注册表画流程条、把体交给 `SectionNav` 渲染成"一张纸"。
- ⚠ **tab key 一个都没改**（通知 link / `?tab=` 深链 / `ROUTE_REDIRECTS` 全靠它）。
- **默认页签写进注册表**（`defaultTab`）：改造中途我让壳取"第一个"，结果采购台从「采购池」变成「待我审批」
  —— 用户点进来看到 0 条的审批队列。默认页签是**行为契约**，不是实现细节。

## 4. 决策（客户已认可「照你的建议」）

1. **待办类改队列行、台账类保留表格** —— 判定法见 §2（已落地于采购/仓库/发运/售后）。
2. **≤4 项直接一行 Segmented，>4 项才加组页签**；9 个台一律画出这条（发运台原来完全没有）。
3. **一件事只在一个台成队列**：叫车归**采购台**（发运台只做"车叫回来后我该装/该发"）；
   别的台只给"数字 + 跳链接"。
4. **筛选器降级**：发运/现场原来把"选中的项目"当家结论 → 现在是**固定槽位**（结论条之下、流程条之上），
   换个页签它还在原地。

### 本轮教训（又各踩一次，已写进规矩）

1. **改文件前先 `cp` 备份**：本轮我又用 `git checkout --` 把售后台的转换还原了一次（第二次犯）。

## 6.1 切换器样式统一（客户实测「采购车间、仓库现场的 tab 样式不一样」）

**症状**：采购/仓库/现场/车间的切换器**与**商务/工程/项目经理/发运的**看着不是一套**；
而且"项"那一行的选中态几乎看不见（采购池、待下发都没高亮）。

**根因（两条，都是我自己引入的）**：
1. **台内混用了两种组件**：>4 项的台，第 1 级走 `SectionNav` 分组分支里的 **antd 下划线 Tabs**，
   第 2 级才用 Segmented；≤4 项的台走**浅色按钮行**（`ds-sec`）。同一屏里既有下划线又有胶囊。
2. **选中态被主题吃掉**：paper.css 只给了 `.ant-segmented` 轨道底色，没给选中项定义样式 →
   浅底 + antd 默认白拇指在白底纸上等于隐形。

**修法（一条规格，落进代码）**：

| 位置 | 组件 | 尺寸 |
|---|---|---|
| **台内第 1 级**（组 / 视图 / ≤4 项时的唯一一行） | `Segmented`（胶囊） | default |
| **台内第 2 级**（组内的具体队列） | `Segmented` | `small` |
| 详情页「分区条」 | `ds-sec` 浅色按钮行（**不动**，它是比台条更轻的一档） | — |

- `SectionNav` 新增 `variant: 'section' | 'flow'`（台壳传 `flow` → 全部用胶囊）与 `flowSize`
  （页面自己还有一条更重的视图条时用 `small`，例如车间台的「看板/制造/装配」）。
- 选中态显式定义：**白底 + 品牌色 + 半粗 + 轻阴影**（`.ds-subtabs .ant-segmented-item-selected`）。
- **车间台去掉了"在制流程/返工与外协"这一层组**（只有 2 组，平白多一行横条）→ 车间 = 视图条(大) + 5 个队列(小)，
  与采购/仓库/现场的"大 + 小"两行完全同构。

**统一后实测（9 个台 + 3 个车间视图）**：每一行都是胶囊、**每行都有可见选中态**、层级一律"大=第 1 级 / 小=第 2 级"。

## 7. 护栏（`SHELL-台骨架四件套`，已注入反例自证能红）

1. 9 个台页必须用 `<WorkbenchPage>`，**不许**再直接用旧的 `<WorkbenchTabs>`（防两套框架并行）。
2. 台页里**不许**有 antd 默认空态（`locale={{ emptyText: <Empty description=…> }}`）。
3. 每个 BoardDef 必须声明 `defaultTab`（且在自己的页签里）。
4. 声明 `kind: 'queue'` 的台，页面里必须真有队列行（`<QueueBoard|<QueueRow`）。

反例验证：去掉 `defaultTab` → 红；把 `<WorkbenchPage>` 换回 `<WorkbenchTabs>` → 红；
把队列行全换掉 → 红；**还发现并修了护栏自己的盲区**（映射式声明 `kind: (…) ? 'queue' : 'ledger'`
只匹配字面量会漏掉 8 个台）。

## 9. 两个教训（写给下一个会话）

1. ★ **绝不要对"工作区已改动过"的文件用 `git checkout -- `**：这一轮因此丢失过两个页面的**未提交呈现层改动**
   （采购台、现场台、工程台、售后台各一次，功能没丢、呈现层丢了要重做）。
   正确的回退手段是**改前 `cp` 备份**、或先 `git commit`。
2. ★ **大批量文本手术必须先断言锚点存在**：`items={[` 会先撞上 `Metrics items={[`；
   JSX 注释不能当 `return (` 的第一个表达式；条件展开 `...(cond ? [...] : [])` 会把括号配对带偏。
   这一轮 4 次"体被删掉"都是锚点/上下文没断言。
