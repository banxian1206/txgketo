## 全程纪律（红线）

1. **每步三关**：`tsc` + `build` + `e2e`——任何一关红，revert 这一步，不带病前进
2. **重构 PR 不许出现视觉 diff**（1.5 视觉收敛除外，且只动颜色/图标/字号不动布局）
3. **业务规则零改动**：接口契约、状态机、权限码、路由路径、编号 一律不碰
4. **一次只动一个域**，独立 commit：`refactor(仓库域): 双壳化` 可单域回滚
5. 新代码必须用基座（AppModal/useSubmit/字段组件/theme）——review 发现手搓即打回

## 依赖与风险

| 风险 | 对策 |
|---|---|
| 重构期间业务仍在改，冲突不断 | Phase 1 尽快（3~5 天）；Phase 2 按域切，冲突面=一个域 |
| e2e 依赖系统 Chrome | 1.0 固定 `channel:'chrome'`；CI/他机需装 Chrome（决策 0.1③） |
| 双端合一是最大手术 | 试点先行（仓库/现场）→ 绿了才推广；域级 revert 兜底 |
| 离线队列做浅 | 3.2 只承诺"暂存+排队+重试"，字段级冲突留真机试点后补 |
