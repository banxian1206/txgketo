> 2026-09-23 起草 · 2026-09-24 **v2 修订（角色台模型，见 §2.0，拍板点以 §6+ 为准）** ｜ 状态：**待拍板**
> 取代旧版《后台页面重构方案》（仅 admin 三页，范围已升级为全站）
> **目标**：登录进来**焕然一新** —— 结构保持「左菜单 · 右内容」，但**侧栏只留一级（21 项 → 7 项）**，二级用**右侧内容区顶部 Tab 切换**（用户明确方向）。

## 1. 现状诊断（实测）

### 1.1 侧栏 21 项平铺，三组名实不符

```
现状侧栏（AppLayout Menu，21 个二级项全部平铺）：
工作台组    我的工作台 · 商务部 · 项目经理 · 工程部 · 采购 · 仓库 · 车间   ← 7 个角色台挤一组
业务组      我的任务 · 商机/项目 · 设计评审 · 改版 · 制造 · 装配 · 发运 · 现场 · 验收 · 售后 · 供应商  ← 11 个
基础数据/管理 标准库 · 编号规则 · 用户与权限                              ← 两类心智混装（业务字典 vs 管理配置）
```

| 问题 | 实测/分析 |
|---|---|
| 找一个功能要扫 21 行 | 侧栏长、组内无层次；**业务组 11 项与交付流程 S5→S11 的天然分段脱节** |
| 7 个工作台 = 7 个菜单项 | 它们本质是**同一页面的 7 个视角**；`GET /workbench/me` 早就返回 `[{key,name,route,visible}]` —— **右侧 Tab 数据源现成**，却被拍平成菜单 |
| 无一级图标 | 分组靠纯文字标题，扫视锚点弱 |
| 混装 | 「基础数据 / 管理」一组里既有业务天天用的标准库，又有管理员低频的用户权限 |

### 1.2 三页三种骨架，页面间不归整（"焕然一新"要解决的舒适度）

- Users=页签流（883 行 4 页签、单页签 1798px 高、演示账号按钮混生产 UI、审计日志藏第 4 页签）
- Library=左侧类别栏+表；NumberRules=多卡片（工具卡与规则表平级）
- 全站缺统一的**页头 / 筛选条 / 表格密度 / 间距**标准（登录页已立 8 系纪律，站内未铺开）

### 1.3 各业务页的二级切换现状

制造/装配/发运/现场/验收/售后 6 页内部**各自已有 Tabs**（页内页签：如发运的"待发/批次"、仓库的"待办/库存/流水/库位"）——**页内 Tab 与"域间切换"是两层**，本方案收的是**域间**这层（侧栏二级 → 右侧顶部），页内 Tab 保持不动。

## 2.0 角色台模型 v2（2026-09-24 方向修正 · **优先级高于后文**）

> 用户方向（原话提炼）：**“我作为采购，进入系统看到的就是我的采购工作台，所有工作内容都在这里（下采购单、催到货、管理供应商）”**；
> **“仓库、采购、车间（现场）、商务都在整条流程线上 —— 把各自职责范围分清楚，按这个划分。”**
> 本节修正两处旧文：① 台 = 角色的**完整工作空间**（含操作现场），不再按“看板只读 / 业务操作”分家；
> ② 侧栏终态收敛为 **5 项**（§2.1 的 7 项为 P0 中间态）。

### 2.0.1 设计原则

1. **台 = 角色的完整工作空间**：我职责内的事务、专业对象、管理动作全部收进我的台（下采购单/催到货/管供应商都在采购台内）
2. **流程线定职责**：S0→S11 每一段归属一个角色台，边界按“谁在这一段干活”切
3. **跨角色对象留全局**：项目详情（全角色都要点进去）、标准库/编号规则（多角色共用字典）、系统管理（管理员）
4. **同一批内容只有一个侧栏入口**（台），业务组不再与台抢入口 —— 消灭重叠的根
5. **台内分区用页签（台内 Tabs），台间切换用域 Tab** —— 两层视觉形态必须区分（下划线 vs 卡片/胶囊）

## 2. 目标信息架构：三层 + 二级右置（核心）

### 2.1 侧栏 21 项 → 7 项（用户三分类落地）

```
┌ 工作台          → 右侧顶部 [角色 Tabs]（数据 = /workbench/me 的 visible 列表原样 7 台：\n│                  我的·商务·项目·工程·**采购(/purchase)**·**仓库(/warehouse)**·车间；P0 已实装+断言）
│
├ 业务
│   ├ 我的工作     → 右侧 [我的任务 | 设计评审 | 改版申请]      ← 干活入口三合一
│   ├ 项目        → 商机列表页（详情 / 立项 / 设计面是下钻页，与 Tab 无关）
│   ├ 交付执行     → 右侧 [制造 | 装配 | 发运 | 现场 | 验收 | 售后]  ← S5-S11 流程线，天然一体
│   ├ 供应商       → 独立项（业务对象，路径 /suppliers）
│   └ 基础数据     → 右侧 [标准库 | 编号规则]
│
※ **修正（2026-09-23 用户纠偏）**：`采购工作台(/purchase)` 与 `仓库工作台(/warehouse)` 是
  `/workbench/me` 里的**角色台**（按 visible 可见）—— 归**工作台域 Tab**，不属业务组；
  初版把「采购」放业务组是身份误判（采购台=角色台，同一页面双重身份）。
│
└ 系统管理（仅 canManageUsers）
        → 右侧 [用户与权限 | 操作日志(/audit 新建独立页)]
```

- **侧栏每一项 = 一个域**，一级带图标（Home / Checklist / Folder / Truck / Cart / Database / SettingOutlined）——扫视锚点，低成本的"焕新"利器
- 系统管理吸收旧「基础数据/管理」组的管理项，**标准库/编号规则归业务**（它们是设计/采购的日常字典，不是配置）
- 上一版 admin 方案的三件事（操作日志独立 /audit、用户页签 4→2、演示按钮收下拉）**并入本方案 §5-P3**

### 2.2 二级 Tab = 子路由（深链接三原则）

右侧 Tab **不是本地 state，而是子路由**：

```
/delivery/mfg · /delivery/assembly · /delivery/shipping · /delivery/site · /delivery/acceptance · /delivery/service
/mine/tasks · /mine/reviews · /mine/changes
/purchase/orders · /purchase/suppliers
/library · /numbering            （或 /base/library · /base/numbering）
/admin/users · /admin/audit
/workbench · /workbench/sales …  （保持现路径，Tab 驱动）
```

三原则：**① 刷新不丢当前 Tab ② 通知里的 link 永远能开（旧路径 301 式 redirect：`/manufacturing → /delivery/mfg`）③ URL 可分享**。
收益：现 e2e 的 `goto 旧路径 → 断言内容` 断言**大多不破**（redirect 后照常渲染），只需补 Tab/新路由断言。

### 2.3 右侧顶部 Tab 形态（统一组件）

新建 `components/domain/DomainTabs.tsx`：
- `Tabs type="line"` + `items` 来自域配置（label / path / 权限条件），**当前子路由自动选中**
- 位置：内容区顶部、页头之下，高度固定 40，**与页头共享 16px 内容边距**
- ≤6 个直接平铺；权限不可见的 Tab 不渲染（如系统管理的子项对非管理员）
