## 2. 高危（建议先修这三条）

### F1 ★ 任何 422 校验错误 → **整站白屏**（不是"报错提示难看"，是页面内容清空）

**复现（3 次点击，真实手滑场景）**
1. `sales1` 登录 → 商机详情 → 点「成交登记」
2. 弹窗里点「+ 添加付款节点」→ **新行什么都不填**
3. 点「确认成交」

**实测证据**
```
POST /projects/TX26005/deal → HTTP 422
{"detail":[{"type":"missing","loc":["body","payment_terms",4,"node_name"],
            "msg":"Field required","input":{}}]}
pageerror: Objects are not valid as a React child
           (found: object with keys {type, loc, msg, input})
    at PureContent (antd.js:9547)     ← antd message 的内容区
提交后 document.body.innerText 长度 = 0     ← 整页没了
```

**根因（两处，叠在一起才炸）**
1. `frontend/src/api/http.ts:27`
   ```ts
   return anyErr?.response?.data?.detail ?? anyErr?.message ?? '操作失败'
   ```
   假设 `detail` 一定是**字符串**。FastAPI 对 Pydantic 校验错误返回的是**对象数组**
   → 数组被塞进 `message.error(...)` → React 渲染对象 → 整棵树崩。
2. `frontend/src/components/project/DealModals.tsx:180`
   ```tsx
   rules={field.name === 0 ? [{ required: true, message: '填节点名' }] : undefined}
   ```
   **只有第 0 行付款节点必填**（第 159 行的自定义校验也只查 `first`）→ 空行能提交到后端 → 必然 422。

**为什么影响面大**：AGENTS §8.2 ⑧ 记录过"必填项治理 = 后端 422 强校验 + 前端红色校验"。
也就是说**系统里凡是走 422 的地方都具备白屏条件**（成交登记、商机、以及其他 schema 校验不过的写接口）。

**建议**
- `errMsg()` 特判数组：`detail.map(d => (d.loc ?? []).slice(-1)[0] + '：' + d.msg).join('；')`，并且**永远返回 string**；
- 付款节点**每行**都必填 + 「+ 添加付款节点」用 `add({ node_name: '', ratio: ... })` 预填空值；
- 基线补一条护栏：**任何一次提交后断言 `body.innerText.length > 0` 且无 pageerror**（这条能同时兜住所有 422 类崩页，成本一行）。

### F3 ★ 4 处 `validateFields()` 裸抛 → 校验失败时抛出的是**非 Error 对象**

**复现**：`purchase_manager` → `/purchase?tab=vehicle` → 行上「叫车」→ **什么都不填**直接点「确认已叫车」
```
校验提示：「装货的人要知道当天几车」   ← 这句文案是对的、很好
PAGEERROR: Object                     ← 但抛出来的是个对象，没有栈
```
（弹窗没关、没提交成功 = **行为正确**；坏在"错误被抛成对象"）

**根因**：`frontend/src/components/VehicleModal.tsx:48`
```ts
onOk={() => {
  form.validateFields().then(async (v) => { ... })   // ← 没有 .catch()
}}
```
antd 的 `validateFields()` reject 的是 `{ values, errorFields, outOfDate }` **普通对象**，不是 Error。
**全站扫描（同种写法）共 4 处**：
| 文件:行 | 场景 |
|---|---|
| `components/VehicleModal.tsx:48` | 采购叫车 |
| `features/admin/IntegrationPanel.tsx:154` | 保存外部集成配置 |
| `features/admin/IntegrationPanel.tsx:167` | 测试连接 |
| `features/shipping/Page.tsx:533` | 发运（清点/装车一类） |

项目里**正确写法**到处都是（`try { v = await form.validateFields() } catch { return }`），这 4 处是漏网的。

**影响**：错误监控里只会留下 `Uncaught #<Object>`（没有 message、没有栈），线上真出问题时**查不到是谁**；
同时也说明"校验失败"这条路径从来没被自动化覆盖过。

**建议**：4 处改成 try/catch；补一条静态护栏——`validateFields()` 必须出现在 `try {` 之后或紧跟 `.catch(`（我上次给 PREFILL 护栏踩过"断言太松"的坑，这次要**注入反例自证能红**）。

## 3. 中危（口径错 / 会被误判 / 该拦没拦）

### F4 项目详情头卡「设备 N」**口径错**：明明 2 台设备，显示「设备 0」
- 实测：立项完成提示"设备 2 台 · 节点 8 个 · 团队 12 人 · 任务 8 条"，但详情页头卡写 **`设备 0`**。
- 根因：`features/project/DetailPage.tsx:382` → `equipments: kitting.length`（**齐套概览的条数**顶替了设备台数）。
  刚立项时还没有 BOM/齐套数据 → `kitting` 为空 → 0。
- 影响：PM/销售每天扫一眼这排数字，会以为"设备没建上"，是**误判**（也是我最早报过的一条假问题）。
- 建议：用设备清单条数；头卡上「发运批次 / 未收」等口径顺便一起核一遍。

### F5 「拍照识别库位」入口是**纯图标按钮**，没有任何可访问名
- 实测（DOM 取属性）：`{ text: "", aria: null, title: "" }`，Tooltip 文案"拍库位标签，自动认库位号"只在鼠标悬停出现——**手机端没有 hover**。
- 我自己第一遍就是按"识别/📷"文字去找这个入口，**没找到**，误报了"手机端没有 OCR 入口"。
- 建议：加 `aria-label="拍照识别库位"`，图标旁给 2 字标签（"识别"）；手机端不能只靠 Tooltip。

### F6 入库成功提示把库位名**重复**了一遍
- 实测文案：`已入库：GR26020 → 导轨暂存架 A-03-12 导轨暂存架`（label 已是"名称 编码"，消息又拼一次名称）。

### F7 「看图纸」在没有附件时依然可点，且把 axios 原文甩给用户
- 实测：点设计面/制造页的「看图纸」→ `GET /drawings/TX26027-01A-00-00-00-00/file → 404`
  后端返回的是**人话**：`{"detail":"…还没上传图纸文件"}`
  但屏幕上显示的是：**`Request failed with status code 404`**
- 说明：这个下载入口走的不是 `errMsg()` 那条链（`AuthedFileLink`），拿不到 `detail`。
- 建议：无附件时**禁用/不显示**「看图纸」；错误统一走人话。

### F8 同一设备可以**无限重复装配**，没有拦也没有提示
- 实测：`01A` 攒出 **3 条**「调试完成」的装配记录（每次跑一遍就多一条）。
- 后果：装配记录/齐套快照重复堆积；将来算成本工时会重复计；发运台"待发设备"判断只看最新一条，容易读错。

### F9 现场**勘测 / 申请调试**同样可重复提交
- 实测：TX26027 的 `site_survey` **4 条**、`site_commission` **5 条**（4 条"已申请" + 1 条"调试完成"）。
- 连带后果：**通知也重复发**——我在 `site1` 的消息区看到连着 4 条「现场申请调试：TX26027」。
  （`notify.daily_key` 只挡"同一天同一 key 的重复提醒"，挡不住"人重复点提交"。）
- 建议：同项目已有"未完成"的调试申请时，入口置灰或提示"已有 1 张待处理，是否再开一张？"

### F10 合并下单**单价不预填**，120 倍的错价一路走到总监那一步才被点出来
- 实测：采购池里 `BZ-DG-0001` 历史价是 **¥9.9**（上次买 3 根），但下单弹窗里
  5 个数字框**全是空的**；我随手填 **¥1200/根**（合计 ¥8,400）→ 采购员提交、经理审批，都没提示；
  直到**总监**的审批面板才显示：`¥1200 含税 高于历史最高 ¥9.9`。
- 说明：价格证据链是有的（`price-reference`/`recommend`），但**没在录 entry 的那一刻用**；
  而且**单价留空也能提交**（= 免费下单，靠后面人工兜）。
- 建议：① 有历史价就预填 + 灰字写"上次 ¥9.9 / 均价 ¥9.9"；② 偏离历史最高 N 倍时**在提交前**红字确认；③ 单价为空要不要允许提交，这是业务口径 —— **需要客户拍**（我倾向允许"暂缺价"但必须填原因）。

### F11 PM 台「验收与质保」页签**没有项目筛选器**，多个项目的验收单混在一张表
- 实测：PM 台两个页签 `["看板","验收与质保"]`，切过去之后 `select 个数 = 0`，列表把所有项目的验收单一起列。
  我在"选了 TX26027"的上下文里点行内操作，实际点到的是 **TX26001** 的单 → 返回
  `这张验收单已经确认过（已通过），不能重复确认`。
- 影响：这是**跨项目误操作**的口子（验收签字、资料签收都是签字类动作）。
- 建议：这一页跟随 PM 台所选项目过滤；行上把项目号+客户做成强标识；操作按钮上带项目号确认文案。

### F12 不存在的路由**静默渲染成工作台**，不出 404
- 实测：`/mfg`（真实路径是 `/workbench/shop/mfg`）、`/acceptance`（真实是 `/workbench/pm?tab=acceptance`）等
  都能"打开"，看到的是工作台样式的页面，URL 也没变。
- 影响：旧书签/外部链接/我们自己的文档链接进来，看到的是"空工作台"，很容易以为**数据丢了**（AGENTS §8.5 的教训就是这个场景）。
- 建议：`path="*"` 给一个真的 404 页（"这个地址没了，点这里回工作台"），或把已知旧路径全部收进 `ROUTE_REDIRECTS`。

### F13 采购下单要两级审批，但**仓库侧完全没有"审批中"的线索**
- 实测：`PO26036` 提交后状态「待经理审」→ 我切到 `wh1` 手机端「待验收」，**没有这条货**；
  总监通过之后才出现。仓库看到的只是"没有活"。
- 口径本身没问题（没批准的单不该让仓库收），但**缺一句解释**。
- 建议：待验收空态加一行："另有 N 张采购单在审批中（采购部可见进度）"——或者干脆不显示，但要在采购台的审批页签上写清"通过后仓库才能收货"。

## 6. 值得肯定的地方（同一次走查里确实顺的）

这几条不是"没坏"，是**明显按人的动线设计过**，值得保留并继续照这个标准做：

1. **立项页**：① 团队 ② 设备 ③ 节点 ④ 长周期件 ⑤ 任务分派，顶部 `○/✓` 清单实时告诉我还差什么；
   「一键生成标准节点」「生成任务」一次点完，最后「确认立项（进入执行中）」是**灰到亮**的。
2. **设计面评审**：按钮上写「提交（已勾 1 项）」——**动态计数**，不用我数；
   经理本人提交时评审记录里明写「经理跳过 · 经理本人提交，跳过一级（05 卷 §0.1#13）」，**把规则解释在界面上**。
3. **发运口径在 UI 上是硬的、而且会说人话**：
   `本批一项都没勾「已发」，不能装车——先到「发运清单」勾选实际发出的件并拍照`
   `先拍这个件的发货照片，再勾「已发」`（没拍照时 checkbox 直接 disabled）
   装车要求先叫车，而**叫车在采购台**（跨部门），采购台「待叫车」页签就把批次接住，登记后回来说"发运可以装车了"。
4. **仓库手机端动线**：卡片 → ① 拍照 → ② 验货（合格/不合格）→ 提交验收 → 待入库 → 选库位入库；
   库位为空时**硬拦**且文案是人话（"入库必须定库位：没有的先到仓库台「库位」页新建，也可以拍库位标签自动认"）。
5. **拍照识别库位整条真跑通了**：拍标签 → 候选 `A-03-12` → 点「用它」→ 回填 → 入库成功（**没有自动填入**，铁律⑦守住了）。
6. **验收→质保是自动的**：客户签字（王主管）之后阶段自己跳到「质保」，头卡显示 `质保 2026-10-02 ~ 2027-10-02`；
   重复申请被拦住：`这个项目已经通过客户验收（质保期已开始）—— 重复申请会覆盖质保起算日`。
7. **回款按节点触发**：预付款的 `trigger_node=立项`（客户口径 Q-5）落库正确，4 个节点全部登记到「已收齐」；
   登记弹窗明说"可多次登记，未收不超总额"。
8. **审批链**：合并下单自动进「待经理审→待总监审」，两级都能看到价格历史对比。
