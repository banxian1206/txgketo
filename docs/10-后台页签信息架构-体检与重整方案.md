# 10 · 后台页签信息架构 · 体检与重整方案（2026-09-29）

> 只读体检 + 方案，**未改任何代码**。所有结论都有实测证据（HTTP / grep / 源码行号）。
> 相关：AGENTS §8.2「工作台框架（06 卷 B 步）」、`frontend/e2e/static.mjs` 的 NAV 护栏。

## 0. 结论一句话

页签乱不是"名字取得不好"，是**四个结构性问题叠在一起**：
① **三套驱动机制并存**（子路由 / `?tab=` / 组件 state）；② **最多 4 层页签条叠在同一屏**；③ **域层与页内层的页签是静态数组，完全没按权限过滤**（只有"台"那一层做了自动化）；④ **可见性判断用的是"岗位"而不是权限码**，直接造成「外部集成」页签对 5 个账号（4 位总监 + gm）**看得见、点了必 403**。
另外顺带查出一处该收没收的口子：`/users`、`/audit-logs`、`/roles` 只要登录就能读全量（含每人的权限清单和手机号）——页签隐藏只是化妆，后端不收口就永远只是化妆。

### 1.2 问题 A：三套驱动机制并存 → 刷新丢、不能分享、通知进不去

| 机制 | 谁在用 | 后果 |
|---|---|---|
| 子路由（`/workbench/tasks`） | 台层、域层、我的工作台、车间台 | 刷新不丢 ✅ 可分享 ✅ |
| URL query（`?tab=`） | **只有采购台**（`purchase/Page.tsx:47`） | 同上 ✅（旧 `/suppliers` redirect 也依赖它） |
| **组件 state**（`useState`） | 仓库 / 现场 / 制造 / 售后 / 任务 / 评审 / 改版 / **用户与权限** | **刷新回第一个页签、URL 无法表达、通知/深链无法指到某个页签** ❌ |

> 通知的 link 现在只能指到页面（`/purchase`、`/warehouse`、`/my-tasks`），指不到"采购单的异常那一栏"。这是同一根因的症状。

### 1.3 问题 B：最多 **4 条页签条**叠在同一屏

实测路径（admin 之外，普通角色也会中）：

```
pm1 打开「我的任务」：
  [层1 台]  我的工作台 | 项目经理台                      ← WorkbenchShell（子路由）
  [层2 台内] 待办 | 我的任务 | 设计评审 | 改版申请           ← workbench/Page（子路由）
  [层3 页内] 我的任务 | 我组任务                          ← task/Page（state）
  [层4 页内] 未完成 | 待开始 | 进行中 | 已完成 | 全部         ← task/Page（state）
```
`shop1 打开「制造」`：`[我的工作台|车间工作台] → [看板|制造|装配] → [待下发|在制|待转运|返工|外协]` = 3 条。
四条横条叠下来，第一屏的有效内容高度被吃掉 ~200px，而且**每层语义完全不同**（层1=角色台、层2=视图、层3=归属范围、层4=状态过滤），用户不可能建立心智模型。

### 1.4 问题 C：同一页面被挂了两个入口

`App.tsx:100-103` 与 `119-120`：`Manufacturing` / `Assembly` **同时**挂在 `/delivery/mfg|assembly`（交付执行域）和 `/workbench/shop/mfg|assembly`（车间台）。
代码注释自己写着「v2 拍板③：交付执行组保留，双入口中间态」——中间态一直没收尾，于是同一组件带着自己的 5 个页签出现在两个壳里，页签数量与状态在两处还会不一致（一边 state 重置过）。

### 1.5 问题 D：可见性用"岗位"而不是权限码 → 实测必 403

```
AppLayout.tsx:31   canManageUsers = is_superuser || position === '总监'      ← 岗位判断
admin/Page.tsx     items=[users, org, roles, integration, logs]              ← 静态，全给
platform.py:697    PUT /admin/integrations/ocr → require_permission("system:admin")
```
实测（`system:admin` 只有 ADMIN 角色有）：

```
eng_director      /users=200  /audit-logs=200  /admin/integrations/ocr=403
purchase_director 同上                    同上=403
wh_director       同上                    同上=403
sales_director    同上                    同上=403
gm                同上                    同上=403
```
→ 5 个账号能在「用户与权限」里看到「外部集成」页签，点进去每次请求都 403。这正是本项目 AGENTS 记过的 M-05 同族（**前端必须反映后端**）。

侧栏那关也不是权限码：`AppLayout.tsx:66` 用 `r.perm !== 'mfg' || hasPerm('mfg:view')` —— `'mfg'` 不是任何真实权限码（真实的是 `mfg:view/mfg:edit`），是硬编码的假码，以后加域会被坑。

### 1.6 问题 E：读接口无门禁（页签隐藏的化妆效应）

实测 `site1`（现场服务，权限只有 `site:edit/acceptance:edit/project:view`）：

```
GET /users           → 200  26 行，字段含 phone / org / position / roles / permissions（每人完整权限清单！）
GET /audit-logs      → 200  全量操作日志（谁 何时 做了什么，含 detail）
GET /roles           → 200
GET /orgs            → 200
GET /numbering/rules → 200
```
写是拦住了（`POST /users`、`POST /demo-users`、`POST /library/items` 对 site1 都 403 ✅），**读完全开放**。
后果：①"总监只能管本部门用户"这条范围规则被枚举绕过；②每个人的角色/权限清单对全员可见；③操作日志（含所有经办痕迹）对全员可见。

### 1.7 问题 F：命名 / 计数 / 双端口径不统一

| 现象 | 证据 |
|---|---|
| 四种"等我办"叫法 | 待我**审批**（采购）/ 待我**审核**（评审）/ 待我**裁决**（改版）/ 待我**改版**（改版） |
| 计数有的带有的不带 | 采购台 `采购池 (3 种 / 12 条)`、仓库 `待办 (7)`、现场 `每日汇报 (12)` 但 **勘测 (0)** 也显示；台层规则是 `n>0` 才显示（`WorkbenchShell.tsx:33`），页签层没这条规则 |
| 双端不同构 | 仓库：移动 **3 页签**（待验收/待入库/领料）vs PC **1 个「待办」包三块**；现场：移动 **6** vs PC **5**（客户验收只在移动端） |
| 状态当页签 | 任务页把「未完成/待开始/进行中/已完成/全部」做成 5 个页签（它是**过滤维度**，不是视图） |

## 2. 目标与硬规则（建议直接写进 AGENTS）

1. **一屏只允许一条页签条。** 需要两层就用"台内子路由 + 页签"，第三层一律降级为筛选器（`Segmented` / `Select`）。
2. **页签 = 视图/工作队列，筛选 = 维度。** 状态、归属范围（我的/我组）属于**筛选**，不做页签。
3. **参考数据不与待办混在同一层。** 供应商、价格参考、库位、编号规则、标准库 → 基础数据域；待办队列留在各工作台。
4. **页签条必须来自注册表并按权限过滤**；过滤用**真实权限码**（`mfg:view`，不是 `'mfg'` 这种半截码），禁用 `position === '总监'` 这类岗位判断。
5. **前端的可见性 ⊆ 后端的可调用性**（AGENTS 铁律：前端必须反映后端）。看不到 = 调不到；看得到 = 一定调得动。
6. **页签状态进 URL**（统一 `?tab=`），子路由只用于域/台层。

## 3. 重整方案

### 3.1 结构（三层封顶，语义各不同）

```
侧栏（5 项，真实权限码过滤）              ← 分类
└─ 台/域层（子路由，注册表 + perm 过滤）  ← “我在哪个角色的工作台”
   └─ 页（业务页）
      └─ 页签（唯一一条，?tab= 持久化）   ← “看哪个工作队列”
         └─ 筛选（Segmented/Select/搜索） ← “范围与状态”，不是页签
```

### 3.2 单一事实源：`TAB_REGISTRY`（把手机端已经做对的模式提到全站）

手机端 `MobileLayout.tsx:26-67` 是全站唯一正确的样板 —— 声明式表 + `show: () => hasPerm(真实码)` + `ALL_TABS.filter(t => t.show())`。照它做一份通用件：

```ts
// configs/tabs.ts
export interface TabDef {
  key: string
  label: string | ((n?: number) => ReactNode)
  perm?: string[]            // 真实权限码，任一命中即可（hasPerm = 有其一）
  all?: string[]             // 需全部命中
  counts?: string            // 角标取自哪个字段（0 → 不显示）
  tab?: string               // 深链用的 ?tab= 值（默认 = key）
  adminOnly?: boolean        // 仅 ADMIN 角色
}
export function filterTabs(defs: TabDef[], ctx: { perms: string[]; roles: string[]; impersonated: boolean })
```
- `WorkbenchShell`（台层）、`DomainShell`（域层）、每条页内 Tabs 全部改吃 `filterTabs(...)`；
- 过滤后 **只剩 1 项就不渲染页签条**（省一层噪音）；**0 项则整个页面不可达**（路由守卫做同样的判断，见 3.5）；
- 角标统一 `n > 0` 才显示，来源只用现成的 `counts`（`/workbench/me` 或各台接口），**不为页签新增聚合接口**。

### 3.3 `?tab=` 统一驱动

抽一个 hook（放在 `hooks/useTab.ts`，采购台的写法照搬）：

```ts
export function useTab(fallback: string) {
  const [sp, setSp] = useSearchParams()
  const tab = sp.get('tab') || fallback
  const set = (k: string) => setSp(k === fallback ? {} : { tab: k }, { replace: true })
  return [tab, set] as const
}
```
迁移后：`/warehouse?tab=storage`、`/admin/users?tab=logs`、`/delivery/site?tab=commission` 可分享、刷新不丢；通知 link 可以指到具体页签（现在只能指到页面）。
**兼容性**：旧链接没有 `?tab=` → 落 `fallback`，零破坏；`ROUTE_REDIRECTS` 不动（AGENTS §8.1 说它是永久兼容层）。

### 3.5 后端配套（页签过滤要有牙齿，必须补这四刀）

1. **读接口加权限码**（实测现在只要登录就 200）：
   `GET /users` → `admin:users`（或 `project:view` 的降级视图：只回 id/name/部门，不回 `permissions`/`phone`）
   `GET /audit-logs` → `admin:audit`，且**非 ADMIN 只回本部门子树**（复用 `reviewers._subtree_ids`，与"总监只管本部门"同口径）
   `GET /roles`、`GET /orgs` → 保留可读（选人要用），但 **`/users` 不再回 `permissions` 字段**（每人权限清单不该全员可见）
2. **新增两个权限码**（进 `seed.py` 的 `PERMISSIONS` + 角色表，配套契约断言）：`admin:users`（ADMIN + 各总监）、`admin:audit`（同上）。
   ⚠️ 这两码的**授予范围是要你拍板的业务问题**（拍板 #4），我不自己定。
3. **路由级守卫**：`RequirePerm anyOf=[...]` 包住 `/admin/*`、`/library`、`/numbering`、`/delivery/*`、`/purchase`、`/warehouse`（现在只有 `RequireAuth`，手输 URL 就能进任何后台页）。这是"后端可调用性"与"前端可见性"对齐的必要条件。
4. **伪装（只读）要参与过滤**：`X-Impersonate` 时 GET 可用、写全 403，但页签里"纯写动作"的页签（如采购台待我审批）应显示为禁用/隐藏，避免"以某人身份看"时点进去满屏 403。

### 3.6 词汇与角标规范（写进《前端交互设计规范》）

- 待办页签一律 **「动词 + 我」/「状态」** 二选一，不许四种：`待我审批`（采购单等我批）、`待我审核`（评审等我批）统一为 **「待我审批」**；`待我裁决`+`待我改版` 合并为 **「待我处理」**；`待验收/待入库/待领料/待下单/待下发/待转运/待补货` 保持（都已经是这个格式）。
- 角标：`n > 0` 才显示；`n` 必须来自接口现成 `counts`，**不允许前端自己数一遍**（双数会打架）；计数含义写进 tooltip（如「采购池 (3 种 / 12 条)」保留双数但统一格式）。
- 页签标签**不写角色名**（「待我裁决（总监）」→ 角色由过滤决定，标签里不用再写）。
