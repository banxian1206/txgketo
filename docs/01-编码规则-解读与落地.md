## 1. 顶层结构：一个编号贯穿始终 ★

```
商机 TX26001  ──成交──  订单 TX26001  ──签约──  合同 TX26001  ──立项──  项目 TX26001
     │                                                                      │
     └──────────────────────  同一个编号，一生不变  ─────────────────────────┘
                                    │
                                    └── 所有图纸号、物料号都以它为前缀
```

**这是本套编号体系最重要的一条**：不存在"商机号转项目号"的映射，也不存在重复发号。

对系统的直接含义（**已写入方案 §3**）：
- **系统只用一个根对象**：「项目档案」，它出生时是商机，成交后是合同，执行中是项目，归档后是公司历史资产
- 报价、图纸、BOM、采购、制造、发运、验收、售后**全部挂在这一个号下**
- 售前阶段就能出正式图号（**Q7 完全解决了原来的"售前无号可用"问题**）
- 从商机点进去，可以一路看到这台设备修过几次

### 1.1 为什么项目号必须放在最前面 —— 编号即归属 ★

客户原话：*"为什么要把 TX23026 放在这里？是它**归属这个项目，归属这个合同，归属这个订单**，你知道吧？"*

**编号的第一段就是归属声明**：

```
TX23026  -  01A  -  01  -  00  -  00  -  00
   │         │     └─────── 在设备里的位置（4 组层次码）
   │         └ 哪台设备（本项目第 01 号设备的 A 台）
   └ 属于哪个项目 / 哪个合同 / 哪个订单 / 哪个客户
```

一个零件、一张图纸、一块钣金，**只要看到编号，就知道它是谁家的**。对系统来说带来四件事：

| 收益 | 说明 |
|---|---|
| **不可能串项** | 双工厂、多项目并行时，车间/仓库看到一个件就知道它归哪个合同；发错项目在编号上就说不通 |
| **一键反查** | 任何零件 → 图号 → 设备 → 项目 → 合同 → 客户 → 售后记录 |
| **成本天生可归集** | 采购、工时、外协费用都能按编号段自动归到项目，不需要人工分摊 |
| **非标件天生隔离** | 自制件/定制件编号里带项目号，**不可能被别的项目误领用**；标准件在标准库里不带项目号，**天生可跨项目复用** —— 上一轮的"物料三分"在编号层面就是自洽的 |

## 2. 机械图纸编号

### 2.1 非标（TX 码）

```
{项目号} - {设备号} - {一级} - {二级} - {三级} - {零件}
 TX23026      01A       02      01      00      00
   │            │         └──── 4 组层次码（两位一组，从 01 起，未用补 00）────┘
   │            └ 设备号：01A = 本项目第 01 号设备；01B = 与 01A 相同的第二台
   └ 项目号（商机号 = 订单号 = 合同号）—— 归属声明
```

| 图纸号 | 怎么读 | 层级 |
|---|---|---|
| `TX23026-01A-00-00-00-00` | 设备 01A 的总装图 | 总装 |
| `TX23026-01A-01-00-00-00` | 01A 下面的**第 1 个组件** | 一级组件 |
| `TX23026-01A-02-00-00-00` | 01A 下面的**第 2 个组件** | 一级组件 |
| `TX23026-01A-02-01-00-00` | 第 2 个组件下面的**小组件** | 二级组件 |
| `TX23026-01A-70-00-00-00` | 防护组件 | 一级（保留码 `70`） |
| `TX23026-01A-80-00-00-00` | 电控组件（电气部分固定 `80` 起，层级不足补 `00`） | 一级（保留码 `80`） |
| `TX23026-01A-80-02-01-00` | 按钮盒固定座 | 零件 |

**保留码（已知，待补全）**：

| 码 | 含义 | 出处 |
|---|---|---|
| `01` | 主体组件 | 第 1 页 |
| `70` | 防护组件 | 第 1 页 |
| `80` | 电控组件（电气部分起点，层级不足补 00） | Q2 答复 |
| `90` | 单机设备固定电气组件 | 第 5/6 页（电气侧） |

### 2.2 标准库（复用件）

```
{标准库码} - {一级} - {二级} - {三级} - {零件}
 0FZJ0001     02     02     02     01
```

规则与 TX 码**只在第一段不同**：非标用项目号，标准库用标准库编码。
示例：`0FZJ0001-00-00-00-00`（总成）、`0FZJ0001-01-00-00-00`（主体组件）、`0FZJ0001-02-02-02-01`（一位按钮盒）、`0FZJ0001-02-02-02-02`（二位按钮盒）。

标准库编码形态：`0` + 3 位字母类别码 + 4 位流水（`0FZJ0001`、`0DJJ0001`）。
字母含义推测为设备类别拼音缩写（如 `DJJ` = 点胶机），**待贵司提供完整类别码表**。

## 4. 物料编号

### 4.1 物料三分（Q8）★

一个项目里的物料**只有三种来源**，系统必须严格分开——因为三者走**三条完全不同的执行链**：

| 类别 | 归属 | 举例 | 执行链 | 库存 |
|---|---|---|---|---|
| **标准件**（含原材料） | **不属于任何项目** | 螺丝、电机、马达、PLC、导轨、铝材、方通、板材 | 标准库**引用** → 采购/领用 | 通用库存，可跨项目复用 |
| **自制件** | 项目专属 | 非标机架、钣金、工装 | 图号 → BOM → **车间制造** | 项目物料 |
| **定制件（外购）** | 项目专属 | 自制不了的定制外购件 | 图号 → BOM → **采购/外协** | 项目物料 |

> 客户原话：*"一个项目里面，既有自制件，也有购买的标准件……它们不能归属于某个项目，而是有一个独立的库，项目需要用到的时候去引用就可以了。其他的非标准件都是自制，如果自制不了的，叫外购，但这种不属于标准件，它属于定制件。"*

### 4.2 自制件 / 定制件 —— **图号就是物料号**（已确认）

客户确认：*"**是的，自制件是直接用图号当物料号。**"*

```
物料号 = 图号 = TX23026-01A-01-00-00-00
```

**一个号走到底**：设计出图、采购询价、车间领料、仓库入账、发运清单、现场安装、售后换件 —— 全用同一个号，不需要图号↔物料号的对应关系。

> PDF 第 7 页那套 `{YY}{项目简写}{图号简写}{序号}` 的物料号（如 `242601A01`）**不再需要**。

**定制件**（自制不了、外购的非标件）同属项目专属，也**沿用图号**作为身份，
区别仅在于标记为“外购”，采购时带上厂家/供应商与询价记录。

### 4.3 标准库编码

标准件与原材料**不属于任何项目**，用标准库编码（**三层结构**，见 §5），项目**引用**即可。

### 4.4 物料单父件（固定模板码）

| 父件号 | 用途 |
|---|---|
| `TX00000-00` | 机械物料单父件 |
| `TX00000-01` | 电气物料单父件 |
| `TX00000-03` | 其他物料单父件 |

### 4.5 物料单据类型

| 类别 | 单据 |
|---|---|
| 机械 | 标准物料单、批量物料单、物料更改单、物料追加单、原材料清单 |
| 电气 | 电箱物料单、电箱物料追加单、电箱物料更改单、电气安装物料单 |

## 5. 标准库编码规则（**三层结构，已确认**）

客户表述：*"标准库……应该有一个编码规则。比如导轨的编码规则，铝材的编码是什么，方通的编码是什么。"*
分层确认：*"标准库这里可能需要**分层级**。比如方通下面有很多种型号，但方通本身又属于某一个类别，这就需要分级。……**采购去买的时候，就是买具体的型号**。就像方通一样，可能都有几十上百种型号。"*

### 5.1 三层结构

```
类别（Category）—— 管理维度            原材料            YL
  └─ 品类（Class）—— 汇总/比价维度           方通          FT
      └─ 型号（Item）—— 采购/库存维度          方通 40×40×2.0 Q235   YL-FT-0001
```

```
{类别码}-{品类码}-{型号流水 4 位}
   YL   -   FT   -   0001
```

| 层 | 码位 | 作用 | 举例 |
|---|---|---|---|
| **类别** | 2 位字母 | 管理口径：看大盘、分权 | `YL` 原材料 · `BZ` 外购标准件 · `DQ` 电气件 · `QD` 气动件 · `JJ` 紧固件 · `ZC` 轴承 … |
| **品类** | 2~4 位字母 | 汇总、比价、找供应商、看价格趋势 | `FT` 方通 · `BT` 扁通 · `CG` 槽钢 · `LC` 铝材 · `DG` 导轨 · `PLC` … |
| **型号** | 4 位流水 | **采购下单、入库、领料、计价都在这一层** | `YL-FT-0001` |

**“方通”一个品类下面就是几十上百个型号**：

| 编码 | 品名 | 材质 | 规格 |
|---|---|---|---|
| `YL-FT-0001` | 方通 | Q235 | 40×40×2.0 |
| `YL-FT-0002` | 方通 | Q235 | 40×40×3.0 |
| `YL-FT-0003` | 方通 | Q235 | 50×50×2.0 |
| `YL-FT-0004` | 方通 | 304 不锈钢 | 40×40×2.0 |
| `…` | | | |
| `YL-FT-0107` | 方通 | Q235 | 100×100×5.0 |

其他品类同构：`YL-LC-0007` 铝材 6061-T5 · `BZ-DG-0102` 直线导轨 HGR20-1000 · `DQ-PLC-0031` PLC 某型号。

### 5.2 为什么规格不写进编码（重要）

| 理由 | 说明 |
|---|---|
| **型号太多** | 方通一个品类就上百个型号，把规格编进码位会越来越长、越来越没规则 |
| **有些型号根本不是数字** | 导轨 `HGR20-1000`、PLC `S7-1200 CPU 1214C`、电机品牌型号 —— 这些是厂家字符串，没法编码化 |
| **一码不变原则** | 规格一旦写进编码，改规格就必须换号；写成属性则改属性就行 |
| **可检可比** | 规格做成结构化字段（材质/长/宽/厚/直径）+ 厂家型号 + 品牌，才能实现"按规格找货""同规格比价" |

> 客户举例的 `YL-FT40-0001` 是同一种结构的写法（品类码写成 `FT40` = 40 系列方通）。
> 采用 `YL-FT-0001` 还是 `YL-FT40-0001` **由贵司定**，系统两种都能跑——关键是**品类码表由技术部统一维护**。

### 5.3 三条原则

1. **一物一码，一经分配永不变**（改了规格就新建码，不覆写旧码）
2. **与项目无关**：标准件不挂项目，项目**引用**（同一个 PLC 在 100 个项目里只有一个物料号）
3. **编码只管身份，属性单独存**：品牌、厂家型号、规格（材质/长/宽/厚/直径）、单位、常用供应商、参考价、安全库存、是否常备，作为字段维护
4. **层级固定不乱动**：类别码与品类码由技术部统一维护；新增品类要先定码再录型号

### 5.4 编码与库存的对应

| 层 | 库存策略 |
|---|---|
| 类别（YL/BZ/DQ…） | 管理口径，看采购大盘 |
| 品类（方通/导轨/PLC…） | 汇总分析，供应商策略 |
| **型号（`YL-FT-0001`）** | **实际入库、领料、安全库存、计价都在这一层** |
| 标准设备/模块（`0FZJ0001` 等，带图纸与 BOM） | 项目**借用**，图纸只读、不重新编号 |

### 5.5 规格建模 —— 编码不含规格，但**规格必须完整** ★

客户原话：*"这个编码对应的**规格很重要，你就必须要写全了**。因为我们**采购买的就是这个规格**。规格必须是完整的。
它可能是同样一种型号，有多个规格，所以它的型号可能也不是唯一的。……**你看到这个编码，能不能知道它是个什么样的规格的产品？如果知道就可以了。**"*

#### 六条规则

| # | 规则 | 为什么 |
|---|---|---|
| 1 | **编码不含规格** | 编码只负责“身份”，一经分配永不变 |
| 2 | **规格必填、必须完整** | 采购就是照规格买，规格缺一个参数就可能买错 |
| 3 | **规格是结构化字段，不是一段自由文字** | 每个品类有自己的**规格模板**（见下表）；结构化才能“按规格找货”“同规格比价” |
| 4 | **全系统“编码 + 品名 + 规格”成对出现** | 列表、单据、扫码、打印均如此 —— 这就是“看到编码就知道是什么规格”的实现方式 |
| 5 | **防重复闸门** | “品类 + 规格全字段 + 品牌”重复时**禁止建码**，提示“已有同规格：`YL-FT-0003`” |
| 6 | **品名自动生成** | 由品类名 + 关键规格拼出标准名称，杜绝同一物料被写成多种名字 |

#### 各品类的规格模板（必填字段）

| 品类 | 规格必须包含 | 示例 |
|---|---|---|
| 方通 / 扁通 | 材质 · 截面长×宽 · 壁厚 · 定尺长 | Q235 · 40×40 · 2.0 · 6000 |
| 槽钢 / 工字钢 | 材质 · 型号 · 定尺长 | Q235 · 10# · 6000 |
| 板材（冷板/热板/不锈钢） | 材质 · 厚度 · 宽×长 | Q235冷板 · 2.0 · 1250×2500 |

## 6. 系统落地设计

### 6.1 编号引擎（系统发号，人工不填）

| 对象 | 发号时机 | 关键校验 |
|---|---|---|
| 项目号（商机号） | **建商机时** | 年份一致、流水不重号 |
| 设备号 | 项目下设设备时 | 同项目内唯一；`01A` 已存在时同型第二台自动建议 `01B` |
| 机械图纸号 | 建图时 | 父级图纸必须存在；同级序号不重复；**未用层级自动补 00**；`80/90/70` 保留码合法性 |
| 电气图纸号 | 建图时 | `90` 不可被占用；线体类型码必须在 6 个内；图序 3 位 |
| 非标物料号 | **由图纸自动派生** | 图号必须属于本项目；序号从 01 起 |
| 标准库物料号 | 建标准件时 | 一物一码；规格+品牌+型号重复时提示"已有同款" |
| 清单主题号 | 生成清单时 | 位置码合法、当日序号不重复 |
| 评审单号（RV{YY}{seq:03}） | 首次提交评审时 | 一个任务一张单、多轮共用；全局按年流水（模板不含项目号，跨项目不撞号） |
| 设计发布号（RL{YY}{seq:03}） | 两级审核通过发布时 | 一次审核通过 = 一个冻结批次；全局按年流水 |
| 改版申请号（CR{YY}{seq:03}） | 提改版申请时 | 冻结版本变更的唯一入口；全局按年流水 |

**发号 = 校验 + 占位**：系统维护号码池，杜绝撞号与跳号。

### 6.2 图号 → BOM 自动成树（本套规则最大的红利）

图纸号本身就编码了 BOM 结构，系统据此自动建树：

- 录入 `TX25045-01A-02-01-00-01` → 解析为 设备 `01A` / 一级 `02` / 二级 `01` / 零件 `01`，自动挂到对应节点
- 父节点不存在 → 告警"父级缺失"
- 自动抓**孤儿**（有子件无父组件图）与**空壳**（有组件图无零件）

**设计只要把图号编对，BOM 骨架自动成型，不用再手工搭一遍。**

### 6.3 版本管理：V1 / V2 + 审核发布（Q6）

```
设计师提交 V1 → 发起审核 → 审核通过 → 发布（V1 生效）
现场发现问题 → 在原图基础上重做 → V2 → 审核 → 发布（V2 生效，V1 转为历史）
```

- 图号不变，版本递增；**历史版本只读留档**
- **"当前有效版本"唯一**——车间按哪版干，系统里只有一个答案
- 版本变更自动触发**变更单**：列出关联物料、在途采购、在制件、成本、交期影响

### 6.4 标准件引用而非复制（Q8）

- 项目 BOM 里选标准件 = **建立引用关系**，不复制物料主数据
- 同一个 PLC 被 100 个项目引用，只有一个物料号、一份库存
- 标准件价格/供应商变动，全局一次更新

### 6.5 物料三分 → 三条执行链

```
BOM 行 → 来源类型判定
   ├ 标准件 → 库存领用（不足则触发采购）→ 通用库存
   ├ 自制件 → 车间制造任务（下料/机加/焊接/装配）→ 项目物料
   └ 定制件 → 采购/外协 → 项目物料
```

齐套计算按三种类型分别展开，车间的"缺料"才真正说得清：**是标准件没到、还是自制件没做完、还是定制件在途。**

### 6.6 现场新增 → 手机申请发号

原文要求"现场新增的小车/护栏/工作台等一律重新编号"。系统做成现场可用的闭环：

```
现场手机拍照 → 提交新增项申请 → 技术审核 → 系统发新图号（自动挂正确层次）
   → 生成 BOM 条目 + 变更单 + 采购需求
```

### 6.7 数据字典预置

线体类型码（MZX/ZJX/LHX/CSX/BZX/ZPX）、位置码（CK/XC/BG）、保留组件码（01/70/80/90…）、物料单类型、**常用原材料标准名称 50+ 项**（原文第 8 页）。
