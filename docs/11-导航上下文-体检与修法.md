# 11 · 导航上下文（drill-in 后"我在哪"）· 体检与修法

> 起因（客户实测）：**在商务部工作台点开一个项目，侧栏直接跳去「业务 → 项目」**。
> 结论：这不是那一个链接的问题，是**「我从哪个台进来」这一维在系统里根本不存在**。已修，并焊了护栏。

## 1. 病根

| 机制 | 位置 | 后果 |
|---|---|---|
| 侧栏选中 = **按路径前缀反推** | `configs/domain.tsx matchSidebarKey()` | `/projects/TX…` 命中「项目」（比「工作台」前缀长）→ 选中被抢 |
| 台 Tab 条 = `WorkbenchShell` 包着的路由才有 | `App.tsx` | 详情/新建/立项/设计面都在壳外 → **整条台条消失**，切不了台 |
| 返回口写死 | `ProjectHeader:52`、`DesignHeaderCard`、`InitiatePage:177` | 「← 返回列表」一律去 `/projects` → 把从台里进来的人**彻底踢出台** |
| 手机端底部条同构问题 | `MobileLayout.tsx:81-82` | `/m/accept/:id` 匹配不到任何 tab key → `?? '/m'` → **掉回「首页」** |

**跨域跳转共 19 处**（`nav('/projects…')` 14 + 设计面 5 类），另有 `/projects/new`、`/projects/:no/initiate`；全部同一个后果。**不是一处漏了，是缺一个统一机制。**

## 2. 修法（已实现）

**新增"来源"这一维，放在 URL 里**（不放 router state：要能刷新 / 收藏 / 新标签 / 被 e2e 断言）：

```
/projects/TX26003?from=%2Fpurchase%2Ftab%3Dorders   ← 从采购台「采购单」页签点进去
```

| 件 | 作用 |
|---|---|
| `hooks/useFrom.ts::useGoFrom()` | 19 处 `nav('/projects…')` → `go('/projects…')`，自动把**当前 URL（含自己的 `?tab=`）**写进 `from` |
| `useFrom()` / `contextPath()` | 侧栏选中与台/域条的高亮**都按来源算**（`AppLayout` + `DomainShell`） |
| `useBack(fallbackTo, fallbackLabel)` | 有来源 → 「**← 返回商务部工作台**」并回原页签；无来源 → 保持各页原文案与原行为（「← 返回列表」） |
| 四个详情路由挂进 `WorkbenchShell` | `projects/new`、`projects/:no`、`:no/initiate`、`:no/design/:equip` → **台条不再消失**，URL 一个没改 |
| `MobileLayout` 的 `ALL_TABS[].match` | `/m/accept` 归回「仓库」；底部条不再掉回首页 |
| `RequirePerm` 守卫 | 带 `from` 进来却没权限 → 弹回**他来的那个台**（不再一律丢去「我的工作台」） |

**顺带修掉的一处隐患**：`useBack` 台清单**由 hook 按需自取**，不做模块级缓存 —— 模块级缓存会跨账号脏读（切换用户 / 伪装后拿到别人的台名）。

## 3. 证据（全部浏览器实测，只读）

真实点击路径 12/12：

```
sales1 /workbench/sales → 点项目行 → /projects/TX26003?from=%2Fworkbench%2Fsales
  ✅ 侧栏选中=「工作台」   ✅ 台条=["我的工作台","商务部工作台"]
  ✅ 返回口=「← 返回商务部工作台」   ✅ 点返回 → /workbench/sales
mech_manager /workbench/eng → 设计面 → 同上（← 返回工程部工作台）
sales1 → 「新建商机」→ /projects/new?from=… → 侧栏不被抢、台条仍在
手机端 /m/accept/999999 → 底部条高亮仍是「仓库」(rgb(31,111,235))，不再掉回「首页」
```

**修复前后对照**（同一探针 `navprobe2`，5 个落点）：台条消失 5/5 → 保住 5/5；侧栏被抢 5/5 → 保住 5/5（用真实点击时）。

## 4. 护栏（防回潮）

`frontend/e2e/ui.mjs` 新增 5 条，**自建靶、不许"没数据就跳过"**：
`NAV-drill-in 带来源` / `NAV-侧栏不被抢走` / `NAV-台条不消失` / `NAV-返回口是来源台` / `NAV-点返回回原台`。

★ **注入反例自证能红**：把 `useGoFrom` 改成不带 `from` → 探针从 12/12 掉到 **3 通过 / 9 失败**（侧栏=项目、返回口退回「← 返回列表」、点返回落不到原台），随后还原。

## 5. 还没做的（可选，按优先级）

1. `e2e:api`/`ui` 里给**仓库台/采购台行内项目号**也补一条同款断言（当时该数据态下无可点行，靠 `navclick` 手工验过）。
2. 面包屑（`项目 / TX26003 / 设计面`）——现在只有"返回口"一条链，多层下钻（项目→设计面→改版单）时来源会只记**上一跳**，不是最初那个台。要做成 `from` 链需另设一层（当前无此诉求）。
3. 台条在**从「项目列表」进入详情**时也会显示（因为挂了同一个壳）。它高亮为空（没有来源可推），是诚实的，但也可选择在这种情况下整条不渲染。
