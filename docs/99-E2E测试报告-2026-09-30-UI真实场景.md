## 一、P0 · 主线断在 UI 上

### P0-1 经理「拆分派工」看不到任何组员 → 05 卷 P2 的任务分派走不通

- **谁**：`mech_manager`（机械经理）
- **在哪**：工作台 → 我的任务 → 行内「拆分派工」
- **看到什么**：弹窗里下拉显示**「暂无数据」**，占位文案写着
  **「本专业还没有组员 —— 先到「用户与权限」配人」** —— 但工程部明明有「机械组员」（mech1，ENG_MECH 组，岗位=组员，专业=机械）。
- **根因**（读代码定位，未改）：
  - `features/task/Page.tsx:110-115` 组员筛选条件 = `u.profession === task.profession && u.position === '组员'`
  - 而 `GET /users` 对**非管理者**返回**降级视图**（`routes/platform.py:377`，重整方案 docs/10 §8.1 拍板#5），
    里面 `profession` / `position` **都是 null**（实测：`mech1 → {"profession": null, "position": null}`）
  - → 条件永远为假 → 永远"没有组员"
- **连带影响（实测）**：
  1. 组员在设计面**看不到「我的提交」卡**（卡里只列自己名下的任务）→ 工艺组员 craft1 做完了材料 BOM，**没有提交评审的入口**，只能由经理提交；
  2. 提交人变成经理 → 评审链**自动跳级**（实测 RV26001/RV26002 都记「经理跳过 · 经理本人提交，跳过一级」）→ **两级审核实际退化成一级**；
  3. 文案把人往错的方向赶（去配权限/配人，其实数据都在）。
- **为什么现有护栏没抓到**：e2e/pytest 直接 `POST /tasks/{id}/split`，不经过前端这个过滤器。
- **建议**（不在本轮实施）：拆分用的名单不要用 `/users` 降级视图；要么服务端出 `GET /tasks/{id}/split-candidates`，要么降级视图保留 `profession/position`（这两个不是敏感字段，敏感的是 roles/permissions/phone）。

## 二、P1 · 会造成错数据 / 流程死锁

### P1-1 采购「叫车」在 UI 上没有任何入口 → 发运链路死锁（09 卷 §2.2）

- 装车被硬拦（**实测**，PM 点「装车」提交）：
  `400 采购还没叫车 —— 先由采购按「计划发货日」把车订好（登记几车 + 本次运费），才能装车`
- 但叫车弹窗**只存在于发运台**（`features/shipping/Page.tsx:456`，按钮 `hasPerm('purchase:edit')` 才显示），
  而发运台的路由门禁是 `RequirePerm anyOf={['ship:edit','project:edit']}`（`App.tsx:132`）——
  **采购员两个权限都没有**。实测 `buyer1` 打开 `/delivery/shipping` → **被弹回自己的 /workbench**（采购总监 purchase_director 同样进不去）。
- 采购台里也没有「待叫车」页签/卡片：后端 `GET /purchase/to-vehicle` 存在，但**全站前端代码没有任何调用**（grep 只命中发运台的「待叫车」Tag 文案）。
- **结论**：一条指令指挥两个部门的设计，只落了后端和发运台，采购侧入口缺失 → **UI 上无法完成叫车 → 无法装车 → 无法发运**。
- 本轮为了继续测 S7 之后，只能由 admin 在「用户与权限」给 `buyer1` 临时加「交付发运」角色（**测完已回滚**，`buyer1` 现在只有 PURCHASE）。这属于绕过，不是设计路径。

### P1-2 付款节点没有任何合计校验，且成交以后改不了

- **实测**：成交登记弹窗默认已带 4 条模板（30/40/20/10），再点「+ 添加付款节点」加 4 条 →
  提交成功，toast 直接写着 **「成交登记完成，付款节点 8 条（合计 ¥6,120,000）」**，而合同金额是 **¥3,600,000**（比例合计 170%）。
- 界面上方明明写着「付款方式（比例合计应为 100%）」，但：
  - 前端 `DealModals.tsx:139-150` 的 validator 只校验「第 1 个节点名非空」；
  - 后端 `routes/project.py:276` 循环建节点，**无合计/重名校验**。
- **成交后无法修正**：付款节点只在「线索」阶段随成交登记整体替换（`project.py:250` 阶段判断），
  成交后详情页只有「登记回款」，**没有增/删/改节点的入口** → 170% 的计划永久留在单上。
- 派生错误（实测）：质保金自动带出 ¥1,080,000（30%）；两个金额为空的节点在「付款方式」表里显示 **「已收齐」**（0 欠款=收齐），比"未收"更误导。
- **建议**：提交时校验 `Σpercent==100`（或 Σamount ≤ 合同额），并给成交后的付款节点开一个带审批的修改口。

### P1-3 手机端「本次到货数量」被清空 → 静默按 1 记账

- **实测**（wh1，`/m/accept/<id>`）：把「本次到货数量」框清空后点「提交验收」→
  三笔全部按 **1** 落库：订 4 根 → GR26004 = 1；订 12 件 → GR26005 = 1；订 40 件 → GR26006 = 1（不合格单也记 1）。
  **没有任何提示**，toast 还是正常的「验收合格 → GR26004 待入库」。
- 根因：`features/acceptance/MobilePage.tsx:241` `onChange={(v) => setQty(Number(v ?? 1))}` —— 清空即 1（全站仅此一处）。
- 连锁（都实测到了）：库存 1、领料只能备 1、采购台「订购/已到」显示 1、退换记录显示「1 件」、齐套率按 1 算；
  少记的 39 件不会有任何地方报错（超额有硬拦，**少记没有**）。
- **建议**：清空 = 禁用提交并提示；或至少弹一次「按 1 记账？」的确认。

### P1-4 手机端入库的「库位」是自由文本，不填就凭空造出「深圳仓 / 待定」

- **实测**（wh1，手机端「选库位入库」，什么都不填直接点「入 库」）→
  toast：**「已入库：GR26004 → 深圳仓 待定」**，库里真多了一行 `warehouse='深圳仓', code='待定', name='未指派库位'`
  （`routes/initiation.py:1195` 写死）。同兴高科在**广东肇庆**，"深圳仓"只是示例文案，却成了正式主数据。
- **而且它会出现在主数据视图里**（实测 仓库台 → 库存）：
  `BZ-DG-0001 直线导轨 … 库位=深圳仓 待定` / `QD-QG-0001 气缸 … 库位=深圳仓 待定` ——
  仓管在库存页看到的是两个不存在的仓库；库位页签也会多出一条可点的「待定」。
- 弹窗里只有一行说明「库位填法：深圳仓 A-03-12（不填就进「待定」）」+ 一个 `Input`
  （`features/acceptance/MobilePage.tsx:349-351`、`features/warehouse/MobilePage.tsx:149-152` 两处同构）。
- **手机端没有用统一的 SelectLocation 控件**（grep：`SelectLocation` 只在 PC 的 `features/warehouse/Page.tsx` 用了两处）→
  **手机端入库既选不到已建库位，也就没有「📷 拍照识别库位」** —— 而 OCR 这个功能立项的原话就是"仓库手机端入库时拍照识别库位"（AGENTS §3.1）。
- **建议**：手机端入库换成 SelectLocation（下拉 + 📷），"待定"库位要么不建、要么显式让用户确认；示例文案换成本公司的仓库名。

### P1-5 发货指令能勾进"不能发"的设备，且批次没有撤销口

- **实测**（pm1，发运台）：待发设备表里 02A 显示「装配状态=未装配、能否发=**未装配完成**」，
  但**勾选框没有禁用**（`features/shipping/Page.tsx:322` 的 `getCheckboxProps` 只禁 `in_open_shipment`），点「下达发货指令（2 台）」**后端也不拦** →
  `FH26001 本次设备 = 01A、02A`。
- 后果（都实测）：发运清单只生成 **1 项**（01A 组装体），02A 在批次里但清单里根本没有它；
  批次签收前，01A/02A 都显示「已在发运批次」，而**系统没有批次取消/作废口**（§8.1 已知）→ 02A 装配完成后要发运时出不来。
- **建议**：`ready===false` 的行禁用勾选（或在提交时 400 并说清"哪台不能发、为什么"）。

### P1-6 「发货日」在 UI 上根本没有输入口（09 卷 §2.2 的硬要求）

- 客户口径：PM 定发货日 → 采购**当天**把车叫回来 → 装货的人据此知道当天装几车。
- **实测**：勾选设备后点「下达发货指令」是**直接建单**，没有任何弹窗/日期框；
  批次列表「发货日」列永远显示 **「—」**；DB `shipment.plan_ship_date = NULL`。
- 采购叫车弹窗文案还写着「按 PM 定的『发货日』当天把车订好」→ 采购对着一个不存在的日期叫车。
- API 是支持的（`routes/shipping.py:90 plan_ship_date`），**e2e 脚本走接口填了这个字段，所以自动化一直是绿的**（§8.2 行 0g）。
- **建议**：下达指令时必选发货日（或至少给一个"默认=今天"的可改框）。

### P1-7 「生成领料单（按设备）」不幂等

- **实测**（wh1）：同一设备（TX26001·01A）点两次 → **MI26001（部分领料）+ MI26002（待备料）**，
  两张都是 5 行、都标「3 种缺料」，内容完全重复；库存只有一份（板材/铝型材 6/6 全部被 lock）。
- 后果：第二张永远备不齐，却长期挂在「待领料」待办里；补货后存在**重复领料**的口子。
- 对比：采购池的承诺是"重复点不会重复进池"（§8.1），领料这条没有对齐。
- **建议**：同项目+同设备存在未关闭领料单时，提示"已有 MI26001（部分领料），要继续那张还是新建？"

### P1-8 自制件一旦挂了标准件，就从「零件 / 材料完整性」统计里整体消失

- 根因：`routes/engineering.py:184` `leaves = 无子图 **且** 无标准件行`；
  而 `parts_without_material`（"自制件必须配原材料"）只在 `leaves` 上算。
- **实测对照**（mech1，设计面）：
  | 时点 | 页面提示 | 头部统计 |
  |---|---|---|
  | 新增自制件「测试-只挂标准件的自制件」 | **「有 1 个自制件还没挂原材料（工艺部）」** | 图 7 张 · 组件 2 · 零件 **2**（自制 **2** / 外协 0） |
  | 给它挂 1 行标准件（螺丝）后 | **提示消失**（页面不再报任何缺项） | 零件 **1**（自制 **1** / 外协 0） |
- 后果：**工艺漏配材料不会被发现**（BOM 完整性判"通过"）；设备头显示的零件数/自制外协数失真
  （本项目真实是 3 个零件：机架框架、导轨安装板 自制 + 气缸支座 外协，界面显示 1 个自制 0 外协）。
- **建议**：叶子判定只看"有没有子图"；材料完整性按 `source_type==='自制件'` 的叶子单独算。

## 四、走通的部分（这些是对的，别改坏）

- **编号引擎**：TX26001 / TK26001-8 / RV26001-2 / RL26001-2 / PO26001-3 / GR26001-6 / MI26001-2 /
  PR26001-4 / WX26001 / FH26001 / SV26001 / YL-LC-0001 等**全自动发号**，全程没有一处需要人手工拼编号。
- **状态机与联动**（逐条实测）：
  - 评审两级通过 → 发布=冻结 → **自动进采购池 6 条**（来源=发布批次 RL26001/RL26002、归属项目/设备/申请人都显示）；
  - 经理本人提交 → **自动跳级**并留痕「经理跳过 · 机械经理」；
  - 验收合格 → 待入库；不合格 → 采购「验收不合格」页签 → 换货 → 需求回「在途」+ 退换记录留痕；
  - **直发客户现场**：下单即生成「现场待验收」到货单（GR26001），现场清点后需求转「现场已验收」；
  - 装配完成 → 发运清单**折成 1 个组装体**（不展开零件），未装清单为空即全装齐；
  - 装车硬拦「采购未叫车」；发运 → 到货 → 现场按同一份清单逐项清点；
  - 客户验收通过 → **自动质保**（2026-10-20 ~ 2027-10-20，阶段 交付中→质保）；
  - 收款提醒按业务节点触发（实测 sales1 收到 立项/发货/验收/质保 四条「该收款了」，且只发给项目自己的销售负责人）。
