# 采购母板与现有系统差异核对

2026-10-08｜只读源码核对，未改正式产品、数据库或业务记录。

## 1. 结论与证据范围

先看系统，再校正模板，再接正式页面。母板的视觉可复用，示例业务数据不能作为数据模型。至少存在三种差异：现有字段可接但未聚合；系统没有母板所示完整能力；现有业务与母板相冲突。不能全部称为“缺数据”，也不能为填满样机而加字段。

本轮检查API类型、后端路由/模型/服务、正式采购页面和合并下单组件。未读取当前数据库内容、未登录各角色实测，因此“代码支持”不代表当前库已填有值；需要后续有权限角色的只读核对。查到字段允许NULL时显示“未填写/待确认”，不能填示例值。以下未发现能力仅针对已检索的模型、API和前端入口，不冒称全面运行验证。

## 3. 模板多余或误导的内容

应直接去掉/换真实数据：固定日期与姓名、今天完成数及完成进度、固定经理3人总监6人、示例项目/PO/设备/照片/单价/公告、演示视角工具、“未发号样机单”演示标签、伪上次催货时间。

重复展示应合并：今日待办是任务子集，不把它与任务相加；采购单/到货批次/异常不能当作同一单位求总数量；发运与叫车不建第二套物流流水；问题收件与消息通知不同，一个是业务责任、一个是提醒。

不能按模板遗漏掉的真实能力：手工采购申请（辅料/办公用品等无项目）、非合并定制件、草稿/退回重提/撤回/作废/取消、部分到货、直发现场、价格/金额可见权限、税口径与必要费用。供应商与价格库入口已有安排，不为了母板再做一份管理页。

## 4. 施工顺序

1. 保留视觉标准，冻结进一步添示例字段；本报告作为接线依据。
2. 用只读真实角色样本核对池、单据、验收、发运、项目；列字段填充情况。明确“无记录”和“模型不存在”，不补假记录。
3. 校正母板：可用数据接线；暂不支持的入口隐藏/标未启用；待建设能力单独列，不改变UI风格。一级结构保留，但不能有能提交却不落库的正式假按钮。
4. 先迁采购主线：公共壳→真实需求清单→生成草稿/提交→审批→到货/异常摘要→项目。每段测试真实范围/空态/失败/刷新，保留既有业务入口。
5. 独立补功能：分工与团队范围、催货日志、通用问题；公告和完成计数可后置。新规则回档+后端校验+审计+护栏，不只改前端。
6. 采购母板真实接线验收后，再复用组件迁其余角色。

## 5. 需要业务决定的最小事项（不自行发明）

- 采购公共需求怎样成为某人的职责：按品类负责、主管分配，还是领取？这决定员工/经理/总监范围，现有created_by/requester不能直接顶替。
- 通用问题的接收者由提交人选，还是按问题类型/项目团队自动分配？以及谁可关闭？暂不能根据样机硬编码推断。

价格审批链已定经理→总监；同型号当前下单集合不拆给多供应商已定，本次不再重新问。无价草稿与逐行收货若暂不新增，按现有规则收敛模板即可，不阻碍视觉迁移。
