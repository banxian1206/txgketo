四个可选方向 —— 同一套真数据，三种页面观感

每套都能点进收件箱 / 项目列表 / 项目详情三个真实页面（底部黑色切换条）。 它们共用同一套规矩（字号刻度、8px 间距、圆角、色板、状态表达），差别只在导航模型、密度、层级怎么拉开。 选一套（或"A 的导航 + C 的密度"这种混搭都行），我按它落地到全站。

先说结论：三套都解决了"页面各自为政" —— 因为它们的字号/间距/圆角/颜色全部来自同一张 token 表（见文末）。 真正的区别是：A 最耐看、B 最有"系统感"、C 最高效。移动端 D 与三套共用 token，只换壳。

三套的差别，一句话

方案导航模型信息密度观感关键词我的建议
A 纸面左侧栏（浅色）中克制、现代、耐看、留白多最安全的选择，PC/移动同一气质
B 墨蓝左侧栏（深色，延续现有品牌）中高系统感、控制室、专业想要"一眼是生产系统"就选它
C 密排顶部一行（无侧栏）高高效、数据、终端、极规整表格最多的采购/仓库/财务最省力
D 移动底部 4 项 + 吸底动作一屏一事作业卡、照片优先必做（现场/仓库/车间的主终端）

选定之后我怎么落地（不改后端业务逻辑）

步做什么验收
1把选中的方案抽成 token + 6 个壳组件（AppShell / PageHead / MetricStrip / QueueRow / Rail / ObjectHead），写进 components/ds/，全站只准用这 6 个字号/间距/圆角取值集合 = 允许值，静态护栏盯
2先换 3 张样板页（收件箱 / 项目列表 / 项目详情）—— 就是你现在看的这三屏，接真接口浏览器实测首屏、列宽、状态表达一致
3再套 10 个部门台（页签 51 → ≤4/台，其余变分组），每套一个台跑一次全量旧断言迁移，一条不删
4移动端 6 条动线换成 D 的作业卡（含照片上卡片、同单折叠）触控 ≥44、0 不占位、断网可暂存

⚠ 这些是静态样机（HTML/CSS，零依赖、不进业务代码），只用来定方向；选定后我会把它翻译成 React 组件 + token，不会把这些文件接进系统。
